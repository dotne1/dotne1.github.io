Dreaming — Penetration Test Disclosure Report

TryHackMe Easy · 2026-07-17

Target: 10.67.183.216 Assessment Date: 2026-07-17 Classification: CONFIDENTIAL (lab / TryHackMe)

1. Executive Summary

The Dreaming host exposed SSH and a default Apache site hiding a Pluck CMS 4.7.13 installation under /app. Weak admin credentials and a known authenticated file-upload RCE (CVE-2020-29607) yielded a www-data web shell. Local files under /opt and user histories supplied credentials and a sudo-backed Python script that unsafely interpolated database fields into a shell command, enabling lateral movement to user death. A group-writable system Python library (shutil.py) was then abused so that a scheduled restore.py job running as morpheus executed attacker-controlled code, completing the three-flag objective (Lucien, Death, Morpheus). Root was not required for room completion.

5. Detailed Findings

F-01: Pluck CMS Authenticated File Upload RCE

Severity: High (CVSSv3: 8.8) Affected Component: Pluck 4.7.13 manage files (admin.php?action=files)

Description: After admin authentication, uploading a .phar payload bypasses extension filters and is executed under the web server user (www-data), providing remote command execution.

Steps to Reproduce:

# Login with admin password, then:
curl -b cookies -F 'filefile=@shell.phar;filename=shell.phar' \
  -F 'submit=Upload' 'http://TARGET/app/pluck-4.7.13/admin.php?action=files'
curl 'http://TARGET/app/pluck-4.7.13/files/shell.phar?c=id'

Impact: Full compromise of the web application context; foothold for further privilege escalation.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — network, low auth barrier once password known, full host user impact.

F-02: Weak Pluck Admin Password

Severity: Critical (CVSSv3: 9.8) Affected Component: /app/pluck-4.7.13/login.php

Description: The Pluck admin password was the trivial value password, allowing immediate access to administrative features including file upload.

Impact: Enables F-01 without credential theft.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — effectively unauthenticated if default is unchanged.

F-03: Credentials Stored in World-Readable Scripts

Severity: High (CVSSv3: 7.8) Affected Component: /opt/test.py, /home/death/getDreams.py

Description: /opt/test.py contained a cleartext password used for SSH as lucien. getDreams.py contained MySQL credentials for user death.

Impact: Direct user compromise after web foothold.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — local file read after foothold yields full user access.

F-04: Command Injection via Sudo-Allowed Script

Severity: High (CVSSv3: 8.8) Affected Component: sudo -u death /usr/bin/python3 /home/death/getDreams.py

Description: The script reads dreamer/dream from MySQL and executes echo {dreamer} + {dream} with shell=True. User lucien can INSERT into dreams and run the script via passwordless sudo as death.

Steps to Reproduce:

INSERT INTO dreams (dreamer, dream)
VALUES ('z', ';cp /bin/bash /tmp/dbash;chmod 4755 /tmp/dbash');
sudo -u death /usr/bin/python3 /home/death/getDreams.py
/tmp/dbash -p -c id

Impact: Privilege escalation from lucien to death.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — local, low complexity after lucien access.

F-05: Group-Writable System Library Hijack

Severity: High (CVSSv3: 8.8) Affected Component: /usr/lib/python3.8/shutil.py (mode 0664, group death); /home/morpheus/restore.py (scheduled)

Description: death can modify the system shutil.copy2 implementation. restore.py imports copy2 and runs periodically as morpheus, executing the modified library code as that user.

Impact: Privilege escalation from death to morpheus (and arbitrary code as morpheus).

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — local modification + trusted automation context.

F-06: Sensitive Material in Shell History

Severity: High (CVSSv3: 7.5) Affected Component: /home/lucien/.bash_history

Description: MySQL CLI invocations retained the lucien database password in history.

Impact: Accelerates credential reuse after partial compromise.

6. Remediation Recommendations

  1. F-01 / F-02: Upgrade Pluck beyond 4.7.13; enforce strong unique admin passwords; disable public install paths; restrict file upload types with server-side allowlists (not extension denylists alone).
  2. F-03 / F-06: Remove secrets from source and history; use environment variables or a secrets manager; rotate all exposed passwords.
  3. F-04: Never pass database fields into shell=True; use parameterized APIs; drop unnecessary sudo; principle of least privilege on MySQL grants.
  4. F-05: System libraries must be root-owned 0644; remove group write; run cron jobs with minimal privileges; integrity-monitor /usr/lib.
  5. General: Disable Apache directory listing on CMS data paths; rate-limit and alert on auth lockouts without using lockout as sole control.
