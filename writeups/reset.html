Reset — Penetration Test Disclosure Report

TryHackMe Hard · 2026-07-17

Target: 10.66.190.44 (HayStack.thm.corp) Assessment Date: 2026-07-17 Classification: CONFIDENTIAL Domain: thm.corp

1. Executive Summary

This assessment targeted the TryHackMe Reset domain controller (Windows Server 2019, HayStack.thm.corp). Guest/null SMB access exposed onboarding material and allowed RID user enumeration. AS-REP roasting yielded domain credentials for TABATHA_BRITT. An ACL abuse chain (GenericAll / ForceChangePassword) led to DARLA_WINTERS, who was configured for constrained delegation. S4U impersonation of Administrator for CIFS/HayStack.thm.corp provided Domain Admin–level access and both flags. A parallel path uses forced NTLM authentication via a writable SMB share to recover the AUTOMATE account (user flag holder).

5. Detailed Findings

F1 — Guest / Null Session SMB Exposure

Severity: Medium (CVSSv3: 6.5) — AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N

Anonymous and guest access to SMB allowed share listing and read access to Data\onboarding (welcome email with default password ResetMe123! and example user LILY ONEILL). Guest RID cycling enumerated domain users and groups.

Remediation: Disable guest and null sessions; restrict share ACLs; remove secrets from world-readable shares.

F2 — Kerberos AS-REP Roasting

Severity: High (CVSSv3: 7.5) — AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N

Accounts without Kerberos pre-authentication (UF_DONT_REQUIRE_PREAUTH) returned crackable AS-REP hashes. TABATHA_BRITT cracked to marlboro(1985).

Remediation: Require pre-authentication on all accounts; enforce strong password policy and monitoring for AS-REP requests.

F3 — ACL Misconfiguration Chain

Severity: High (CVSSv3: 8.8) — AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H

From low-privilege domain user:

  • TABATHA_BRITT → GenericAll on SHAWNA_BRAY, RAQUEL_BENSON
  • SHAWNA_BRAY → ForceChangePassword on CRUZ_HALL
  • CRUZ_HALL → ForceChangePassword / Owns / GenericWrite on DARLA_WINTERS

Passwords were reset without knowing prior secrets (net rpc password).

Remediation: Audit AD ACLs with BloodHound; remove non-standard GenericAll/ForceChangePassword; use tiered admin model and Protected Users where appropriate.

F4 — Constrained Delegation to Domain Admin

Severity: Critical (CVSSv3: 9.0) — AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H

DARLA_WINTERS was trusted for constrained delegation to CIFS/HayStack.thm.corp. Using S4U2Self/S4U2Proxy (impacket-getST -impersonate Administrator), an Administrator service ticket was obtained and used with wmiexec for full DC control.

Remediation: Minimize constrained delegation; prefer resource-based constrained delegation with tight controls; monitor S4U requests; protect privileged accounts with Protected Users and auth silos.

F5 — Writable Share Forced Authentication

Severity: High (CVSSv3: 7.1) — AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:N/A:N

Data (and especially onboarding) is writable and actively browsed by automation (AUTOMATE). Planting .url/.scf files captures NetNTLMv2 hashes via Responder.

Remediation: Remove write for standard users; segregate automation accounts; block outbound SMB to untrusted hosts; monitor for NTLM theft patterns.

7. Remediation Priority

  1. Remove constrained delegation from non-essential accounts; protect DAs.
  2. Fix ACL inheritance and ForceChangePassword / GenericAll misconfigurations.
  3. Disable AS-REP roastable accounts and enforce preauth.
  4. Harden SMB (no guest/null; no sensitive data on open shares; no unnecessary write).
  5. Deploy tiering, LAPS/gMSA, and continuous BloodHound-style ACL monitoring.

8. Tools Used
