Penetration Test Disclosure Report

TryHackMe Medium · May 30–31, 2026

Client: Silent Monitor Corp - CorpNet NOC Assessment Date: May 30–31, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the CorpNet NOC portal at 10.66.182.237:5050. The assessment identified four security vulnerabilities that, when chained, allowed an unauthenticated attacker to achieve full remote compromise of the host. Initial access was gained via SQL injection in the login form, followed by command injection in a health-check endpoint that allowed a reverse shell. Lateral movement to the sysadmin account used credentials found in a configuration file on the server, and privilege escalation to root was achieved by cracking a KeePass credential database whose master password was found in the rockyou wordlist.

4. Detailed Findings

F-01: SQL Injection in Login Form

Severity: Critical (CVSSv3: 9.8) Affected Component: POST /internal — Login endpoint

Description: The login form accepts unsanitized username and password POST parameters and passes them directly into a SQLite query string. No parameterized queries or input sanitization is implemented. An attacker can bypass authentication entirely by injecting SQL into the username field.

Steps to Reproduce:

POST /internal HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=admin' OR '1'='1' --&password=anything

The server returns a session cookie granting operator-level access:

Set-Cookie: session=eyJyb2xlIjoib3BlcmF0b3IiLCJ1c2VyIjoibmV0b3BzIn0.ZltV5A.7QedPUPE90SJQjBz2nLl9JgZtSs; HttpOnly; Path=/

Impact: Unauthenticated attacker gains authenticated access to the NOC dashboard and all restricted functionality, including the vulnerable health-check feature.

Recommendation: Use parameterized queries (e.g., cursor.execute("SELECT ... WHERE username = ?", (username,))). Never concatenate user input into SQL strings.

F-02: Command Injection in Health Check Endpoint

Severity: High (CVSSv3: 8.8) Affected Component: POST /internal/health — Health check endpoint

Description: The health check feature accepts a target IP/hostname POST parameter and passes it unsanitized into a subprocess.Popen(..., shell=True) call executing ping -c 2 -W 1 <target>. A character filter blocks ;, |, ` `, $, and &, but the newline character (\n / %0A`) is not blocked, allowing command chaining.

Steps to Reproduce:

POST /internal/health HTTP/1.1
Content-Type: application/x-www-form-urlencoded

target=127.0.0.1%0A<COMMAND>

Arbitrary commands execute as the www-data user.

Impact: Full execution of arbitrary commands on the server as www-data, enabling lateral movement, data exfiltration, and backdoor installation.

Recommendation: Do not use shell=True with subprocess. Parse and validate the target input rigorously — accept only known-good IP addresses or hostnames. Use subprocess.Popen(["ping", "-c", "2", "-W", "1", target]) with a pre-validated target.

F-03: Hardcoded Credentials in Application Config

Severity: High (CVSSv3: 7.5) Affected Component: /opt/netops/secret.config

Description: The backup-agent configuration file is stored in the application directory and is readable by the www-data user (the web application user). It contains SSH credentials for the sysadmin account in plaintext.

Evidence:

[backup_agent]
username = sysadmin
password = S3cur3Backup$Acc3ss!

Impact: An attacker who has achieved command execution as www-data can read this file and gain SSH access as sysadmin, a user with significantly more system privileges.

Recommendation: Store secrets in an encrypted vault or a dedicated secrets manager. Restrict file permissions on any configuration files that must contain credentials. Do not co-locate secrets with web application code.

F-04: KeePass Database with Weak Master Password

Severity: High (CVSSv3: 7.8) Affected Component: /home/sysadmin/backups/infrastructure.kdbx

Description: A KeePass 4.0 credential database containing the root password is stored in the sysadmin home directory with a master password (spring) that appears in the rockyou wordlist (rank ~2301). This database is world-readable by the sysadmin user and contains the root account password.

Evidence (KeePass entry):

Field Value
Title Root User Password - Sensitive
Username root
Password S3cur3P4ss0nK33p4ss

Impact: Any user who can read this database file and crack the password (e.g., by exfiltrating it and running it against rockyou) gains root-level access to the host.

Recommendation: Enforce a strong password policy for password managers (minimum 16 characters, high entropy, not present in common wordlists). Restrict file permissions on the KeePass database. Use multi-factor authentication or SSH key-based access for root.

6. Remediation Priority

Order Finding Action
1 F-01 Use parameterized queries for all database operations
2 F-02 Remove shell=True and validate all user input passed to subprocess
3 F-03 Rotate all exposed credentials; store secrets in a vault or environment variables
4 F-04 Rotate root password; enforce strong master passwords for credential databases
