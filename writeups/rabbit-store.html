RabbitStore — Penetration Test Disclosure Report

TryHackMe Medium · 2026-07-08

Target: 10.65.167.82 Assessment Date: 2026-07-08 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target 10.65.167.82 (RabbitStore). The assessment identified four open ports and a web application with multiple chained vulnerabilities. Initial access was gained through a Server-Side Template Injection (SSTI) in a Node.js/Flask application, leading to user-level access as azrael. Privilege escalation was achieved by leveraging an exposed Erlang cookie for RabbitMQ, extracting hashed credentials from the RabbitMQ definitions, and decoding them to obtain the root password. Full compromise of the target was achieved with both user and root flags captured.

5. Detailed Findings

F-01: Server-Side Template Injection (SSTI) — Jinja2 RCE

Severity: Critical (CVSSv3: 9.8) Affected Component: POST /api/fetch_messeges_from_chatbot

Description: The chatbot endpoint accepts a username parameter that is rendered unsafely inside a Jinja2 template. An attacker can inject template expressions that are evaluated server-side, leading to arbitrary command execution.

Steps to Reproduce:

curl -H "Cookie: jwt=<valid_jwt>" \
  -H "Content-Type: application/json" \
  -d '{"username":"{{ self.__init__.__globals__.__builtins__.__import__(\"os\").popen(\"id\").read() }}"}' \
  http://storage.cloudsite.thm/api/fetch_messeges_from_chatbot

Impact: Full remote code execution as user azrael. Exfiltration of files, installation of SSH keys, pivoting to internal services.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H — Network exploitable, low complexity, requires authentication but no user interaction, scope change, high CIA impact.

F-02: Suboptimal Access Control — Subscription Parameter Manipulation

Severity: High (CVSSv3: 7.5) Affected Component: POST /api/register

Description: The registration endpoint accepts a subscription parameter. Setting it to active during registration grants immediate access to admin-level functionality without approval.

Steps to Reproduce:

curl -X POST -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"test","subscription":"active"}' \
  http://storage.cloudsite.thm/api/register

Impact: Unauthorized access to restricted endpoints including file upload, SSRF, and SSTI endpoints.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N — No authentication required, no user interaction, high confidentiality and integrity impact.

F-03: Server-Side Request Forgery (SSRF) — Internal Service Discovery

Severity: High (CVSSv3: 7.5) Affected Component: POST /api/store-url

Description: The URL fetch endpoint accepts arbitrary URLs and retrieves content from internal services, including the AWS instance metadata service at 169.254.169.254. This leaks IAM credentials and enables discovery of the internal Node.js API documentation.

Steps to Reproduce:

curl -X POST -H "Cookie: jwt=<valid_jwt>" -H "Content-Type: application/json" \
  -d '{"url":"http://127.0.0.1:3000/api/docs"}' \
  http://storage.cloudsite.thm/api/store-url

Impact: Disclosure of AWS IAM credentials, discovery of the SSTI-vulnerable endpoint.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N — Requires auth but grants access to internal resources with high confidentiality impact.

F-04: Exposed Erlang Cookie — RabbitMQ Credential Access

Severity: High (CVSSv3: 8.8) Affected Component: /var/lib/rabbitmq/.erlang.cookie

Description: The Erlang cookie file is world-readable (-r-----r--), allowing any local user to read it. The cookie authenticates Erlang nodes and can be used to issue admin commands to the RabbitMQ cluster.

Steps to Reproduce:

cat /var/lib/rabbitmq/.erlang.cookie
rabbitmqctl --erlang-cookie 'X' --node rabbit@forge export_definitions /tmp/defs.json

Impact: Full administrative access to RabbitMQ, enabling export of user credentials including the root password hash.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H — Local access required, but leads to complete system compromise.

F-05: Weak RabbitMQ Password Storage — Reversible Password Hash

Severity: High (CVSSv3: 7.8) Affected Component: RabbitMQ user database

Description: RabbitMQ stores passwords as base64(salt + sha256(salt + password)). This format allows anyone with the hash and knowledge of the algorithm to trivially recover the password by decoding the base64 and stripping the 4-byte salt — no cracking required.

Steps to Reproduce:

echo -n '<base64_hash>' | base64 -d | xxd -p -c 100 | cut -c9-

Impact: Recovery of the root user's password in plaintext, enabling full root access via su -.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H — Requires local access but trivial to exploit once obtained.

6. Remediation Recommendations

  1. (F-01) Sanitize user input in Jinja2 templates. Use {% raw %}...{% endraw %} or switch to plain string formatting without template evaluation.
  2. (F-02) Remove the subscription parameter from the registration endpoint; implement proper server-side activation workflow.
  3. (F-03) Restrict the store-url endpoint to allow only necessary outbound URLs; block access to private IP ranges (RFC 1918) and the AWS metadata IP.
  4. (F-04) Restrict the Erlang cookie file permissions to owner-only (chmod 400 owned by rabbitmq).
  5. (F-05) Upgrade RabbitMQ to a version that uses a proper password hashing scheme with strong salts and multiple iterations; consider external authentication backends (LDAP, OAuth).
