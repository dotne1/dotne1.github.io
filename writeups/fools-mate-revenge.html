Penetration Test Disclosure Report

TryHackMe Medium · July 4, 2026

Client: Fool's Mate Revenge (Endgame Trainer) Target: http://10.67.184.177:3000 Assessment Date: July 4, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the Endgame Trainer web application at http://10.67.184.177:3000. The assessment identified two chained vulnerabilities that allowed an attacker to extract the application flag. The client-side chess move validation was bypassed by sending API requests directly via curl, revealing a server-side checkmate validation flaw. Additionally, the server accepted arbitrary session configuration parameters in the move request body, allowing the attacker to set session.config.unlocked and bypass the reward gate.

4. Detailed Findings

F-01: Client-Side Validation Bypass via Direct API Access

Severity: High Affected Component: /api/move — POST endpoint

Description: The application uses the chess.js library on the client side to validate all moves before sending them to the server. The starting position (FEN 6k1/5ppp/8/8/8/8/5PPP/R5K1) contains a rook on a1 and king on g1 versus a black king on g8 with pawns on f7, g7, h7. There is no legitimate mate-in-one in this position. However, by sending HTTP requests directly to /api/move via curl (bypassing the client entirely), the server accepts a1a8 (Ra8) as a valid move and declares checkmate, despite the black king having an escape square at f8.

Steps to Reproduce:

$ curl -s -X POST http://10.67.184.177:3000/api/move \
  -H 'Content-Type: application/json' \
  -d '{"from":"a1","to":"a8"}'

Response:

{"ok":true,"move":"a1a8","fen":"R5k1/5ppp/...","status":"checkmate","winner":"white","locked":true,"message":"Checkmate! No reward for you.","reason":"reward gate closed: session.config.unlocked is not set"}

Impact: An attacker can bypass all client-side validation and interact directly with the API, revealing internal error messages and server-side session logic.

Recommendation: Implement server-side move validation using a chess library. Validate that a move is both legal and results in checkmate before declaring a winner.

F-02: Session Config Injection via Move Request Body

Severity: Critical Affected Component: /api/move — POST endpoint body parsing

Description: The /api/move endpoint accepts arbitrary JSON properties in the request body and merges them into the server-side session configuration. By including "config":{"unlocked":true} in the move request, the attacker can set session.config.unlocked on the server. This bypasses the reward gate check and causes the server to return the flag upon checkmate.

Steps to Reproduce:

$ curl -s -X POST http://10.67.184.177:3000/api/move \
  -H 'Content-Type: application/json' \
  -d '{"from":"a1","to":"a8","config":{"unlocked":true}}'

Response:

{"ok":true,"move":"a1a8","fen":"R5k1/5ppp/...","status":"checkmate","winner":"white","flag":"THM{pr0t0_p0lluted_th3_r3f3r33}"}

Impact: An unauthenticated attacker can inject arbitrary session configuration values, bypass access controls, and extract the application flag.

Recommendation: Do not merge entire request bodies into session objects. Strictly validate and whitelist the expected request parameters (from, to, promotion). Implement proper input sanitization for all API endpoints.
