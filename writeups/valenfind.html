Valenfind — Penetration Test Disclosure Report

TryHackMe Medium · 2026-07-17

Target: 10.67.137.234 Assessment Date: 2026-07-17 Classification: CONFIDENTIAL (lab / TryHackMe)

1. Executive Summary

ValenFind is a Flask-based “secure dating” web application exposed on TCP/5000. Authenticated users can load profile layout templates through an API parameter that is joined unsafely to a filesystem path, enabling arbitrary file read on the host. Application source recovered via LFI disclosed a hardcoded admin API token used to download the SQLite user database. The database stored passwords in plaintext and embedded the engagement flag in the privileged cupid account’s address field. No SSH foothold was required; the room objective was fully achieved through the web attack path.

5. Detailed Findings

F-01: Path Traversal / Arbitrary File Read via Layout API

Severity: High (CVSSv3: 8.6) Affected Component: GET /api/fetch_layout?layout=

Description: Profile pages load theme HTML via a client-side call to /api/fetch_layout. The server builds the file path with os.path.join(base_dir, layout_file) and opens the result without normalizing or restricting path components. Absolute paths and ../ sequences allow reading any world-readable (and, because the process runs as root, nearly any) file on the system. Weak denylists block only *.db / cupid.db and the substring seeder.py.

Steps to Reproduce:

# Authenticate (register + login), then:
curl -b 'session=<cookie>' \
  'http://10.67.137.234:5000/api/fetch_layout?layout=/etc/passwd'
curl -b 'session=<cookie>' \
  'http://10.67.137.234:5000/api/fetch_layout?layout=../../app.py'

Impact: Source code disclosure, configuration leakage, credential and secret recovery, and broader host file access enabling further compromise.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N — network reachable after low-privilege registration; confidentiality high; scope changed (reads outside app boundary).

F-02: Hardcoded Admin Token Enables Unauthenticated Database Export

Severity: Critical (CVSSv3: 9.1) Affected Component: GET /api/admin/export_db + ADMIN_API_KEY in app.py

Description: The application embeds ADMIN_API_KEY = "CUPID_MASTER_KEY_2024_XOXO". Presenting this value in the X-Valentine-Token header returns the full SQLite database as an attachment. The endpoint does not require a user session—only knowledge of the static secret, which LFI trivially provides.

Steps to Reproduce:

curl -H 'X-Valentine-Token: CUPID_MASTER_KEY_2024_XOXO' \
  http://10.67.137.234:5000/api/admin/export_db -o cupid.db
sqlite3 cupid.db 'SELECT username,password,address FROM users;'

Impact: Complete compromise of all user credentials and profile data, including the room flag stored in the cupid row.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N — once the key is known, unauthenticated full DB download; high confidentiality and integrity risk (credential reuse / account takeover).

F-03: Plaintext Password Storage

Severity: High (CVSSv3: 7.5) Affected Component: SQLite users.password column; login compares cleartext.

Description: Registration and seeding store passwords without hashing. Any database read (export, LFI of DB if filters fail, backups) immediately yields usable credentials for every account.

Impact: Immediate account takeover for all users; high risk of password reuse against SSH or other services.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N — requires prior access path but impact is total credential disclosure and account control.

F-04: Sensitive Personal Data and Flag in User Profiles

Severity: Medium (CVSSv3: 6.5) Affected Component: Profile fields (real_name, email, phone_number, address, bio)

Description: The app encourages collection of real name, email, phone, and home address. The privileged cupid account’s address field contained the engagement flag. Combined with F-02, all PII is bulk-exfiltrable.

Impact: Privacy breach for all users; secret material stored as ordinary profile data.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N — confidentiality of personal data without requiring multi-step privilege elevation beyond DB access.

F-05: Web Application Runs as Root

Severity: Medium (CVSSv3: 5.5) Affected Component: systemd service valenfind / process environment

Description: /proc/self/environ and process metadata show the Flask app executing as USER=root. Any future RCE or additional file-write bug would yield immediate root compromise.

Impact: Elevates impact of all application bugs from app-user to full system control.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N scored as a compounding misconfiguration; standalone local impact medium, critical when chained with RCE.

6. Remediation Recommendations

  1. F-01: Resolve layout names against an allowlist of known theme files; use os.path.realpath and enforce a fixed base directory prefix before open(). Never pass raw user input into path joins.
  2. F-02: Remove hardcoded secrets; load admin credentials from a secrets manager or environment variables; require strong mutual auth (mTLS or short-lived tokens) and session-bound admin roles for export endpoints.
  3. F-03: Hash passwords with a modern KDF (bcrypt/argon2id); never store or compare plaintext.
  4. F-04: Minimize PII collection; do not store secrets/flags as profile fields; encrypt sensitive columns at rest where required.
  5. F-05: Run the app under a dedicated unprivileged service account with least privilege and a hardened systemd unit (NoNewPrivileges, private tmp, restricted filesystem).
  6. General: Disable verbose path error messages; add authentication rate limiting; rotate all exposed credentials after this assessment.
