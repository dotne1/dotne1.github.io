Penetration Test Disclosure Report

TryHackMe Easy · May 31, 2026

Client: Silver Platter Corp Assessment Date: May 31, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target environment at 10.66.135.148. The assessment identified five security vulnerabilities that, when chained, allowed an unauthenticated attacker to achieve full remote compromise of the host. Initial access was gained via an authentication bypass in the Silverpeas web application (CVE-2024-36042), followed by a broken access control vulnerability (CVE-2023-47323) that leaked SSH credentials for a low-privileged user. From there, credential reuse and excessive sudo privileges enabled lateral movement and privilege escalation to root.

4. Detailed Findings

F-01: Silverpeas Authentication Bypass (CVE-2024-36042)

Severity: Critical (CVSSv3: 9.8) Affected Component: /silverpeas/AuthenticationServlet

Description: Silverpeas versions prior to 6.3.5 permit authentication bypass by omitting the Password POST parameter. The server treats the absence of this field as an SSO-based login, granting access as the target user.

Steps to Reproduce:

POST /silverpeas/AuthenticationServlet HTTP/1.1
Content-Type: application/x-www-form-urlencoded

Login=1&DomainId=0

Impact: Unauthenticated remote attacker gains superadmin privileges.

Recommendation: Upgrade to Silverpeas >= 6.3.5.

F-02: Broken Access Control on Messages (CVE-2023-47323)

Severity: Medium (CVSSv3: 6.5) Affected Component: /silverpeas/RSILVERMAIL/jsp/ReadMessage.jsp

Description: The messaging feature does not authorize the ID parameter, allowing any authenticated user to enumerate all internal messages.

Impact: Confidential data leak. SSH credentials for user tim were discovered in Message #6.

Recommendation: Upgrade to Silverpeas >= 6.3.2.

F-03: Database Credentials Exposed in System Logs

Severity: High (CVSSv3: 7.5) Affected Component: /var/log/auth.log (world-readable by adm group)

Description: The PostgreSQL database password was passed as a command-line argument to docker run and recorded in plaintext in the system authentication log. Any user in the adm group (including low-privilege user tim) could retrieve it.

Evidence (from /var/log/auth.log.2):

Dec 13 15:40:33 sudo: tyler : ... docker run ... -e POSTGRES_PASSWORD=_Zd_zx7N823/ ...

Impact: Exposed database password enabled lateral movement via password reuse.

Recommendation: Never pass secrets as command-line arguments. Use Docker secrets, environment files with restricted permissions, or a secrets manager.

F-04: Password Reuse Across Application and OS Accounts

Severity: High (CVSSv3: 8.0) Affected Accounts: tyler (OS), silverpeas (PostgreSQL)

Description: The PostgreSQL database password _Zd_zx7N823/ was identical to user tyler's OS login password, enabling lateral movement from tim to tyler.

Impact: Full compromise of the tyler account, which held sudo privileges.

Recommendation: Enforce unique passwords across all systems and applications. Implement a password manager.

F-05: User tyler Granted Unrestricted sudo Access

Severity: High (CVSSv3: 7.8) Affected Component: /etc/sudoers / sudo group membership

Description: User tyler is a member of the sudo group, granting full root execution privileges with no restrictions.

Impact: Complete host compromise.

Recommendation: Apply the principle of least privilege. Restrict sudo rights to specific commands with appropriate auditing.

6. Remediation Priority

Order Finding Action
1 F-01 Upgrade Silverpeas to >= 6.3.5
2 F-02 Upgrade Silverpeas to >= 6.3.2
3 F-03 Rotate all exposed credentials; audit log retention; stop passing secrets on CLI
4 F-04 Enforce unique passwords per service
5 F-05 Audit sudo group membership and apply least privilege
