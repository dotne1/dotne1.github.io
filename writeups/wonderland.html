Wonderland — Penetration Test Disclosure Report

TryHackMe Medium · July 7, 2026

Target: 10.67.130.30 Assessment Date: July 7, 2026 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target running Ubuntu 18.04.4 with a custom Go web server and OpenSSH. The assessment identified 5 security vulnerabilities ranging from Critical to Medium severity. Initial access was gained through hidden credentials discovered in the web application, after which Python import hijacking, insecure sudo configuration, SUID binary abuse, and Linux capabilities abuse were chained to achieve full root compromise.

4. Detailed Findings

F-01: Hidden Credentials in Web Application Source

Severity: High (CVSSv3: 7.5) Affected Component: GET /r/a/b/b/i/t/

Description: The web application contains a hidden HTML paragraph element (<p style="display:none">) on the path /r/a/b/b/i/t/ that exposes valid SSH credentials (alice:HowDothTheLittleCrocodileImproveHisShiningTail). The path is obtained by traversing a directory-based puzzle at /r/ that spells out "rabbit" one letter at a time.

Steps to Reproduce:

curl -s http://10.67.130.30/r/a/b/b/i/t/ | grep display:none

Impact: An attacker can SSH into the target as the alice user, gaining initial access to the system.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — Network-based, low complexity, no privileges required, high CIA impact.

F-02: Sudo Misconfiguration Allowing Privilege Escalation

Severity: High (CVSSv3: 7.8) Affected Component: /etc/sudoers.d/alice

Description: The user alice is allowed to execute /usr/bin/python3.6 as the rabbit user via sudo without a password. The rule permits execution of a specific Python script, but the Python interpreter itself can be leveraged to execute arbitrary code as rabbit through module import hijacking.

Steps to Reproduce:

cat /etc/sudoers.d/alice
# alice ALL = (rabbit) /usr/bin/python3.6 /home/alice/walrus_and_the_carpenter.py

Impact: Allows escalation from alice to rabbit user.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — Local access, low complexity, requires alice access.

F-03: Python Import Hijacking via Sudo

Severity: High (CVSSv3: 7.8) Affected Component: /home/alice/walrus_and_the_carpenter.py

Description: The Python script walrus_and_the_carpenter.py (owned by root) imports the random module without using a fully-qualified path. Python's sys.path starts with '' (current directory), so a malicious random.py placed in /home/alice/ is imported before the system library. When the script is executed via sudo -u rabbit, the malicious code runs as rabbit.

Steps to Reproduce:

# Create /home/alice/random.py containing:
import os
os.system("cp /bin/bash /tmp/rshell && chmod 4755 /tmp/rshell")

# Then execute:
sudo -u rabbit /usr/bin/python3.6 /home/alice/walrus_and_the_carpenter.py

Impact: Arbitrary code execution as the rabbit user.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — Local, low complexity, requires alice access.

F-04: SUID Binary with Unsafe system() Call

Severity: High (CVSSv3: 7.0) Affected Component: /home/rabbit/teaParty

Description: The /home/rabbit/teaParty binary has the SUID bit set (owner: root) and calls setuid(1003) to drop privileges to the hatter user, then invokes system("/bin/echo -n 'Probably by ' && date --date='next hour' -R"). The date command is called without a full path, allowing PATH hijacking. A malicious date script placed in a directory earlier in $PATH will be executed as the hatter user.

Steps to Reproduce:

export PATH=/tmp:$PATH
# Create /tmp/date:
cp /bin/bash /tmp/hshell && chmod 4755 /tmp/hshell
/home/rabbit/teaParty
# /tmp/hshell is now SUID hatter

Impact: Privilege escalation from rabbit to hatter user.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — Local, low complexity, requires rabbit access.

F-05: Linux Capability cap_setuid+ep on Executable

Severity: High (CVSSv3: 7.8) Affected Component: /usr/bin/perl

Description: The /usr/bin/perl binary has the cap_setuid+ep capability set, which allows the program to change its UID to any value via setuid(). The binary is group-owned by hatter with group execute permission. When executed by the hatter user, perl can call POSIX::setuid(0) to become root and execute arbitrary commands.

Steps to Reproduce:

/usr/bin/perl -e 'use POSIX; setuid(0); system("cat /home/alice/root.txt")'

Impact: Full root compromise. Allows reading /root/user.txt and /home/alice/root.txt.

CVSS Justification: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H — Local, low complexity, requires hatter access.

5. Attack Chain Summary

Web Application (hidden creds) → SSH alice
  → sudo -u rabbit + Python import hijack → rabbit user
    → teaParty SUID + PATH hijack → hatter user
      → perl cap_setuid → root

6. Remediation Recommendations

  1. F-01: Remove sensitive information from web-accessible files. Use secure storage for credentials.
  2. F-02: Restrict sudo rules to only allow execution of the specific script with no ability to modify its execution environment.
  3. F-03: Use absolute module imports or set PYTHONPATH securely. The script's directory should not be writable by lower-privilege users.
  4. F-04: Use absolute paths for all commands in system() calls. Do not rely on PATH. Consider dropping privileges more securely.
  5. F-05: Remove unnecessary capabilities from binaries. The cap_setuid+ep capability on perl is equivalent to full root access for any user who can execute it.
