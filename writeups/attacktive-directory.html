Attacktive Directory — Penetration Test Report

TryHackMe Medium · 2026-07-07

Target: 10.65.144.212 (spookysec.local) Date: 2026-07-07 Objective: Capture user flags for svc-admin, backup, and Administrator accounts

The Attacktive Directory engagement targeted the spookysec.local Active Directory environment. Kerberos user enumeration identified the svc-admin account, which was AS-REP roastable and yielded the first set of credentials. Those credentials provided SMB access to a backup share containing base64-encoded credentials for the backup account. The backup account held DCSync replication rights, enabling an NTDS.DIT dump via secretsdump and a Pass-the-Hash authentication as Administrator, achieving full domain compromise.

2. User Enumeration via Kerberos

2.1 Kerbrute

./kerbrute userenum -d spookysec.local --dc 10.65.144.212 userlist.txt

Found valid users: james, svc-admin, robin, darkstar, administrator, backup, paradox

2.2 AS-REP Roasting (Cracked Hash)

svc-admin had "Does not require Pre-Authentication" enabled:

impacket-GetNPUsers -no-pass -dc-ip 10.65.144.212 spookysec.local/svc-admin

Hash Type: Kerberos 5, etype 23, AS-REP
Hashcat Mode: 18200

4.1 Secretsdump via DRSUAPI

7. Remediation Recommendations

  • Disable Kerberos pre-auth for svc-admin: Remove the UF_DONT_REQUIRE_PREAUTH flag to prevent AS-REP roasting.
  • Restrict DCSync rights: The backup account should not have DS-Replication-Get-Changes privileges.
  • Enable SMB signing: Prevent relay attacks.
  • Audit service accounts: Service accounts should have least-privilege access.
  • Use managed service accounts (gMSA): For automated password rotation.
