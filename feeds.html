CVE-2026-77679

Published: 2026-11-27 01:17:03 CDT

Severity: N/A

CVSS Score: N/A

A path traversal (ZIP slip) vulnerability exists in Epiphany when installing WebExtension packages from .xpi files. In src/webextension/ephy-web-extension-manager.c, the decompress_xpi_thread() function extracts XPI archives (ZIP format) to disk using libarchive. For each archive entry, the output path is built by concatenating the intended extraction directory with the raw pathname from the archive: full_path = g_build_filename(path, archive_entry_pathname(entry), NULL); archive_entry_set_pathname(entry, full_path); ret = archive_write_header(ext, entry); The libarchive extraction options did not include ARCHIVE_EXTRACT_SECURE_NODOTDOT or ARCHIVE_EXTRACT_SECURE_SYMLINKS. As a result, archive entries containing parent-directory traversal sequences (for example "../../../../../.bashrc") are written outside the intended web_extensions extraction directory. A malicious .xpi file can therefore overwrite arbitrary files writable by the user running Epiphany, such as ~/.bashrc, ~/.config/autostart/*.desktop, or ~/.ssh/authorized_keys. This can lead to persistent code execution on subsequent shell startup or GNOME login. Exploitation requires the victim to install or open a crafted .xpi file. The reporter notes that opening an XPI can trigger extraction even when the WebExtensions feature is not enabled by default. Affected versions: Epiphany >= 47.rc. Fixed upstream in epiphany 50.6 and 49.9 via merge request !2143, which adds ARCHIVE_EXTRACT_SECURE_NODOTDOT and ARCHIVE_EXTRACT_SECURE_SYMLINKS to archive_write_disk_set_options(). Upstream report: https://gitlab.gnome.org/GNOME/epiphany/-/issues/2922

CVE-2026-125627

Published: 2026-11-27 00:17:08 CDT

Severity: MEDIUM

CVSS Score: 6.5

A **NULL pointer dereference** flaw has been found in the vlv_value_compare() function in vlv_pagination.c of the Virtual List View module in the **Samba** package. The function uses the sort value from the search result with no check that the result still contains that attribute. A low-privileged network attacker or user who can search the directory sends a Virtual List View search by value, sorted on an attribute the matching entries do not have. The LDAP worker that handles the search exits, which disconnects the directory clients that were using that worker, and the directory service starts a replacement worker. Another search of the same kind crashes the worker that accepts it, and each further crash waits longer before that worker is replaced, so repeating the search keeps the LDAP service from staying available. The same crash follows a search sorted on an attribute the attacker is not allowed to read. The directory removes that attribute from the result, and the comparison uses the missing value.

CVE-2026-119072

Published: 2026-11-26 23:19:00 CDT

Severity: MEDIUM

CVSS Score: 5.3

The W3 Total Cache plugin for WordPress is vulnerable to Sensitive Information Exposure in all versions up to, and including, 2.11.0 via the 'utm_source (and the wp-resetpass- cookie on the victim side)' parameter. This makes it possible for unauthenticated attackers to extract the live password-reset key (rp_key) embedded in the cached reset form, enabling full account takeover of the targeted administrator. Exploitation requires the page-cache engine to be configured as Disk: Basic, Memcached, Redis, or APC with the 'Cache URI with query string variables' option enabled, and the victim must visit an attacker-crafted URL containing utm_source=wp-locations.php while their wp-resetpass cookie remains active.
