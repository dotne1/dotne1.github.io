CVE-2026-135779

Published: 2026-11-24 02:17:06 CDT

Severity: N/A

CVSS Score: N/A

Reliance on an untrusted source of the client address in the WebSocket listener of the NetBird relay server (relay/server/listener/ws) in NetBird versions 0.31.1 through 0.74.7 allows an attacker with an enrolled peer to spoof the source address of their relay connection. The listener used the values of the X-Real-Ip and X-Real-Port request headers as the remote address of the connection unconditionally, without checking that the request came from a trusted upstream proxy. A WebSocket client that sends both headers makes the relay record and use an arbitrary address for its connection, including in the relay connection log, so a client can hide its real address or attribute its connection to another host. Only the relay server is affected; the NetBird client, including the Android and iOS apps, does not run the relay listener. The issue is fixed in version 0.75.0, which honours these headers only for requests whose direct connection address is in a configured set of trusted proxies and ignores them by default.

CVE-2026-105431

Published: 2026-11-24 02:17:04 CDT

Severity: N/A

CVSS Score: N/A

A protection mechanism failure in the userspace firewall of the NetBird client (client/firewall/uspfilter) in NetBird versions 0.55.0 through 0.74.6 allows an attacker who controls an enrolled peer to bypass the access control rules of another peer by sending IP-fragmented packets. The packet filter returned an allow verdict for any IPv4 fragment, and for any IPv6 packet carrying a Fragment extension header, before evaluating the ACL rules. This applied to the leading fragment as well as to continuation fragments, so no part of a fragmented datagram was filtered and ports denied by policy could be reached. The userspace filter is the packet filter wherever the client does not program the kernel firewall, which includes the Android and iOS apps. The issue is fixed in version 0.74.7, in the Android app from version 0.6.0 and in the iOS app from version 0.3.3, which evaluate fragments against the same ACL rules as unfragmented packets.

CVE-2026-105430

Published: 2026-11-24 02:17:03 CDT

Severity: N/A

CVSS Score: N/A

Deserialization of untrusted data in the relay server handshake of NetBird versions 0.29.0 through 0.74.7 allows an unauthenticated remote attacker to reach the Go encoding/gob decoder with attacker-supplied bytes before any credential is checked, which can lead to denial of service of the relay server. The deprecated Hello handshake message was still accepted before authentication and its token was decoded with gob.NewDecoder (shared/relay/auth/hmac) before the HMAC signature was verified. The handshake buffer limits the input to 212 bytes and the pre-authentication phase to 10 seconds, so there is no impact on confidentiality or integrity and the impact on availability depends on a separate weakness in the gob decoder of the Go toolchain used to build the relay server, such as CVE-2024-34156. The Auth handshake, used by clients since version 0.29.1, does not use gob. The issue is fixed in version 0.75.0, which removes the Hello handshake and the gob-based token decoding.

CVE-2026-105428

Published: 2026-11-24 02:17:02 CDT

Severity: N/A

CVSS Score: N/A

Binding to an unrestricted IP address in the netstack SOCKS5 proxy of the NetBird client (client/iface/netstack) in NetBird versions before 0.74.7 allows an unauthenticated attacker on the same network as the client to relay traffic through the client into its NetBird overlay network. When the client runs in netstack mode (NB_USE_NETSTACK_MODE=true), it starts a SOCKS5 proxy, without authentication, that is meant to bridge applications on the local host into the userspace WireGuard stack. The listener was bound to 0.0.0.0 instead of the loopback address, so any host that can reach the proxy port (1080 by default) can connect and reach peers and internal resources with the network position of the affected client. Netstack mode is not enabled by default. The issue is fixed in version 0.74.7, which binds the proxy to 127.0.0.1 by default.
