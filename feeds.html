CVE-2026-71411

Published: 2026-11-26 08:17:37 CDT

Severity: N/A

CVSS Score: N/A

GNU Screen is vulnerable to a Time-of-Check/Time-of-Use (TOCTOU) race condition in the hardcopy file handler. Due to checking write permissions using the real user ID and subsequently opening the file using the effective user ID, a local unprivileged attacker can atomically replace the target path with a symbolic link pointing to an arbitrary system file. Successfully exploiting this race condition allows the attacker to write to arbitrary files with root privileges, leading to local privilege escalation This issue was fixed in version 5.0.2.

CVE-2026-71410

Published: 2026-11-26 08:17:37 CDT

Severity: N/A

CVSS Score: N/A

GNU Screen is vulnerable to a Use-After-Free in the utf8_handle_comb() function in encoding.c. Due to improper error handling during memory allocation failure, the global combchars pointer is freed but not reset to NULL. When a subsequent combining Unicode character arrives at the terminal, the function dereferences the freed pointer. An attacker who controls terminal content sent to the screen session, such as via a rogue SSH server or crafted escape sequences, can exploit this vulnerability to perform heap grooming and achieve arbitrary code execution. This issue was fixed in version 5.0.2.

CVE-2026-137594

Published: 2026-11-26 08:17:27 CDT

Severity: N/A

CVSS Score: N/A

MISP contains an authorization flaw in the SharingGroup model's checkIfAuthorisedExtend method. The method grants sync users (those with the perm_sync role) an exemption from the extend flag requirement when modifying sharing group membership. However, this exemption was applied unconditionally to all sharing groups, including those created locally on the instance (local = 1). The intended behavior, consistent with the sync push path, is that the exemption should only apply to sharing groups received through sync from another instance (local = 0). As a result, an authenticated sync user whose organization was a plain member (extend flag = 0) of a locally-created sharing group could add or remove organizations and servers from that group via the quick-edit actions or the edit form. This bypassed the extend-flag authorization that is required for non-owner members to modify a sharing group's membership. Preconditions: the attacker must possess an authenticated account with the sync role (perm_sync) and the sharing group permission (perm_sharing_group), and must be a member of the target locally-created sharing group without the extend flag set. The attacker does not need to be the group owner or a site administrator. Security impact: an unauthorized modification of sharing group membership can alter which organizations and servers are permitted to exchange threat intelligence data through that group. An attacker could add their own organization to gain access to shared indicators, or remove other organizations to disrupt their data exchange. The scope of impact is limited to the integrity of the sharing group membership configuration and does not directly expose or corrupt stored threat intelligence data.
