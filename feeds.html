CVE-2026-93585

Published: 2026-11-23 08:17:27 CDT

Severity: HIGH

CVSS Score: 8.8

An improper authorization vulnerability in the EV Reach Client Agent allows authenticated users with low privileges to execute arbitrary commands on a remote Windows endpoint with LocalSystem privileges. The affected agent service does not sufficiently enforce authorization restrictions for certain privileged remote management operations. Under specific conditions, the agent fails to apply the intended user impersonation mechanism and executes user-supplied commands within the security context of the agent service, which runs as NT AUTHORITY\SYSTEM. As a result, an authenticated attacker may bypass the intended privilege restrictions and execute arbitrary commands with the highest user-mode privileges on an affected Windows system. Successful exploitation may lead to complete compromise of the affected endpoint, including unauthorized access to sensitive information, modification of system configurations, installation of malicious software, or disruption of system availability.  The vulnerability does not require administrative credentials or user interaction after successful authentication.

CVE-2026-86312

Published: 2026-11-23 07:17:06 CDT

Severity: HIGH

CVSS Score: 8.8

Under some configurations a request to the ping endpoint could carry out more than a simple health check. In deployments that rely on Solr's rule-based authorization, a client granted only the low-privilege health permission could thereby trigger behavior that should require higher privileges; where the shipped security.json template leaves the health permission unauthenticated, no credentials are required at all.  This issue affects Apache Solr from 9.0.0 through the releases preceding the fixed versions. Users are recommended to upgrade to version 9.11.0 or 10.1.0, which resolve the issue. You are affected if you run an affected version and allow the /admin/ping endpoint to be reached with only the health permission. This includes the default sample security configuration installed by the bin/solr CLI, where that endpoint is unauthenticated. Users who cannot upgrade immediately should restrict access to the /admin/ping endpoint in their authorization configuration — for example by requiring a trusted role for that path — and ensure Solr is not reachable from untrusted clients or networks, as recommended for all Solr deployments.

CVE-2026-53672

Published: 2026-11-23 07:17:05 CDT

Severity: MEDIUM

CVSS Score: 6.5

A bug related to the Zookeeper HTTP endpoints in Apache Solr allows an authenticated attacker with zk-read permission to read /security.json, bypassing the security-read authorization check. This may cause unauthorized read of credential hashes and authorization configuration. For this attack to be successful, the following must be true * The system is secured with Solr's Basic Auth plugin * The attacker has gained direct network access to the Solr cluster * The attacker has obtained credentials for a user account with zk-read permission (which is recommended assigned to trusted admins only) Users are recommended to upgrade to 9.11.0, 10.1.0 or a newer release. Users who cannot upgrade immediately are recommended to assign the zk-read permission only to users who they entrust reading security.json.

CVE-2026-125651

Published: 2026-11-23 07:17:03 CDT

Severity: N/A

CVSS Score: N/A

Cleartext storage in encrypted parquet file vulnerability in Apache Arrow Rust (`parquet` crate), from version 55.0.0 through to 57.3.2, 58.4.1, 59.3.2 and 60.1.0. When writing an encrypted parquet file with a column with bloom filters, the header and bitsets of the bloom filter are written in plaintext in the final parquet. Users are recommended to upgrade to versions 57.3.3, 58.4.2, 59.3.3 or 60.2.0 which fix the issue by raising an error when trying to write encrypted parquet files with bloom filters enabled, preventing such files from being written out. Existing encrypted parquet files written with bloom filters are still vulnerable, and it is recommended to rewrite those files with bloom filters disabled if possible.
