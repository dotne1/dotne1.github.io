Severity: HIGH

CVSS Score: 7.7

CVE-2026-135262

Published: 2026-11-23 10:17:46 CDT

Severity: N/A

CVSS Score: N/A

MISP contains a DOM-based cross-site scripting (XSS) vulnerability in the Pivot Explorer component. The bundled pivotick visualization library (version 1.2.0) rendered all string values it received as HTML markup rather than as plain text. As a result, user-controllable data fields, including attribute comments, attribute values, and reference relationship types, were interpreted and executed as HTML/JavaScript in the Pivot Explorer tooltip and sidebar panels. An authenticated user with the ability to create or modify MISP attributes could embed malicious HTML or script payloads in these fields. Preconditions: - The attacker must have authenticated access to create or modify MISP attributes (comments, values, or reference relationship types). - The victim must open the Pivot Explorer and interact with or view the affected event data in the tooltip or sidebar. Security impact: Successful exploitation allows arbitrary script execution in the victim's browser within the MISP application origin, enabling theft of session credentials, manipulation of displayed data, and execution of privileged API calls on behalf of the victim. Affected versions: MISP prior to 2.5.52.

CVE-2026-135261

Published: 2026-11-23 10:17:46 CDT

Severity: N/A

CVSS Score: N/A

MISP's brute-force lockout mechanism for login and one-time-password (OTP) authentication is susceptible to bypass through Unicode case-folding inconsistencies and input handling flaws. - Email addresses containing non-ASCII capital letters are not counted toward the lockout threshold, permitting unlimited authentication attempts against a specific account. - Database collation folding (accent and width variants) allows an attacker to reach a valid account using a folded alias of the email address without the attempt being recorded in the lockout counter. - A password containing a NUL byte produces a distinct server error for known accounts while unknown accounts receive a different response, enabling username enumeration. An unauthenticated remote attacker can exploit these issues to perform unlimited password brute-force attacks against any account and to enumerate valid user accounts. Affected: MISP versions prior to 2.5.52

CVE-2026-135260

Published: 2026-11-23 10:17:46 CDT

Severity: N/A

CVSS Score: N/A

MISP contains multiple flaws in its login and one-time-password (OTP) brute-force lockout mechanism that collectively weaken authentication protection. - Lockout counter bypass: the lockout stored and matched usernames using a single-byte case-fold function. An email address containing a non-ASCII capital letter (for example a Latin-1 or Cyrillic uppercase) was never counted toward the lockout threshold, allowing unlimited failed login attempts against that account. - Collation-folding authentication bypass: the database collation performs accent and width folding, so a Unicode variant of a valid address (e.g. a different diacritic or a full-width character) resolved to the same account during authentication while the lockout treated it as a distinct, untracked identity. An attacker could therefore authenticate as the target user using a folded alias without triggering the lockout. - Username enumeration via NUL byte: submitting a password containing a NUL byte caused the hashing routine to raise an exception, producing an HTTP 500 response for a known account but a different response for an unknown one, disclosing valid usernames. Preconditions: the target MISP instance is reachable over the network and the login endpoint is exposed. No prior authentication is required. Security impact: an unauthenticated attacker can perform unlimited password-guessing against accounts whose address contains a non-ASCII capital, can authenticate as a user via a Unicode-folded alias, and can enumerate valid usernames. Successful exploitation leads to account takeover. Affected: MISP versions prior to 2.5.52.

CVE-2026-135259

Published: 2026-11-23 10:17:45 CDT

Severity: N/A

CVSS Score: N/A

MISP contains a type confusion vulnerability in the authentication key creation endpoint. When a user submits a floating-point value as the target user identifier, the authorization check truncates the value to an integer (matching the attacker's own account), while the persistence layer rounds the same value to a different integer (the next account in the sequence). This discrepancy allows an authenticated user with key-creation permission to generate an API authentication key belonging to another user. Preconditions: - The attacker must be an authenticated user with the permission to create authentication keys. - The target user must have a consecutive numeric identifier immediately following the attacker's identifier. Impact: - Unauthorized creation of an API key for another user, granting the attacker access to that user's data and operations within the MISP instance. - The vulnerability is trivially exploitable by substituting a carefully crafted floating-point value for the integer user identifier in the request. Affected versions: MISP prior to 2.5.52.

CVE-2026-135258

Published: 2026-11-23 10:17:45 CDT

Severity: N/A

CVSS Score: N/A

MISP contains multiple related authorization and input-validation flaws in its object editing and attachment handling workflows. - A user with permission to edit their own object could inject a foreign attribute identifier into the object revision form. The revision data, stored in the server-side session, was merged into the stored object before the save diff was computed. The save then wrote to the foreign attribute row by its identifier without verifying that the row belonged to the caller's event or organisation, allowing an attacker to overwrite or soft-delete an attribute in another organisation's private event. - Attachment file paths were constructed directly from event and attribute identifiers supplied by the request. Because no type or format validation was applied, crafted values (for example directory-traversal sequences or file-name extensions) could cause the application to read from or write to file-system locations outside the intended attachment directory. - The audit-log behaviour recorded an edit under the event identifier carried in the save payload rather than the event identifier of the stored database row. An attacker who included a different event identifier in the save could cause the audit entry to be attributed to the wrong event, undermining the integrity of the audit trail. Exploitation requires an authenticated web-session user with object-editing permissions (perm_add / perm_modify). API-key-only requests do not carry the PHP session and are not affected by the revision-session vector. Affected versions: MISP < 2.5.52. Fixed in 2.5.52.

CVE-2026-135257

Published: 2026-11-23 10:17:45 CDT

Severity: N/A

CVSS Score: N/A

MISP contains an improper output sanitization vulnerability in the Zeek (Bro) intelligence export functionality. The export module constructs tab-separated lines for downstream Zeek/Bro intelligence feeds. The sanitization routine was intended to strip tab, newline, and carriage-return characters from user-controlled fields (organisation names and attribute values) before they were embedded into the export line format. However, the sanitization pipeline applied character replacement before HTML entity decoding, meaning that HTML entities such as (tab), (newline), and (carriage return) survived the initial pass and were subsequently decoded into actual separator characters. Additionally, organisation names were inserted into the export format string without any sanitization at all. An authenticated user with the ability to create or modify events, organisation names, or attribute values could embed HTML-encoded separator characters. When the Zeek/Bro export was generated, these characters would split a single export line into multiple lines or introduce extra tab-delimited fields, corrupting the structured intelligence feed consumed by downstream Zeek/Bro deployments. Security impact: - Integrity of exported intelligence data is compromised; downstream Zeek/Bro systems may process malformed or split entries. - Corrupted intelligence lines could lead to incorrect blocking, alerting, or logging decisions in the consuming environment. Affected versions: MISP prior to 2.5.52.

CVE-2026-135256

Published: 2026-11-23 10:17:45 CDT

Severity: N/A

CVSS Score: N/A

MISP contains a Regular Expression Denial of Service (ReDoS) vulnerability in its Warninglist feature. Warninglist entries of type "regex" are evaluated against attribute values without any backtracking limit. An authenticated user with permission to add or import warninglist entries can supply a crafted regular expression pattern that triggers excessive backtracking in the PCRE engine, causing sustained CPU consumption and denial of service. Additionally, imported warninglists were not validated for syntactic correctness before replacing existing entries, allowing malformed or malicious patterns to be persisted and later evaluated without prior rejection. Preconditions: - An authenticated account with the ability to create, edit, or import warninglist entries (users below site-admin level can add entries). - The target MISP instance has at least one warninglist of type "regex" that will be evaluated against incoming attribute values. Impact: - Sustained CPU exhaustion leading to denial of service for all users of the MISP instance. - Potential for cascading performance degradation on shared infrastructure. Affected versions: MISP prior to 2.5.52.

CVE-2026-135253

Published: 2026-11-23 10:17:44 CDT

Severity: N/A

CVSS Score: N/A

MISP's NIDS rule export functionality for Snort and Suricata formats does not properly escape user-controlled data before embedding it into generated rule text. Attribute values, tag names, and URL paths are inserted directly into rule options (msg, metadata, content matches) without neutralizing characters that are syntactically significant in the NIDS rule grammar, such as double quotes, semicolons, backslashes, commas, and control characters. An authenticated user with the ability to create or modify attributes in a MISP instance can craft attribute values or tag names containing these special characters. When the NIDS rules are exported, the unescaped data breaks out of the intended option or content field, allowing injection of arbitrary rule options, corruption of rule structure, or generation of syntactically invalid rules that may cause the downstream NIDS engine to reject the entire ruleset. The affected export paths include: - Snort and Suricata msg: option (quotes, semicolons, backslashes, control characters) - Suricata metadata: option (commas, semicolons, quotes, whitespace, control characters) - Suricata http.uri content: match for URL path (quotes, semicolons, pipe characters) Security impact is limited to the integrity and availability of the exported NIDS rules and the downstream NIDS engine that consumes them. There is no direct compromise of the MISP application itself. Affected: MISP versions prior to 2.5.52.

CVE-2026-135252

Published: 2026-11-23 10:17:44 CDT

Severity: N/A

CVSS Score: N/A

MISP contains a Server-Side Request Forgery (SSRF) vulnerability in its feed and sync HTTP request handling. When the application uses libcurl as the HTTP transport, the CURLOPT_FOLLOWLOCATION option was enabled by default, causing the library to automatically follow HTTP redirects without the application's own per-hop validation logic being invoked. - Feed requests: MISP implements its own redirect validation for feed sources, but libcurl was following redirects before that validation could execute, allowing a malicious or compromised feed source to redirect the request to arbitrary internal URLs. - Sync requests: Sync peers are server-configured, and the application does not perform per-hop redirect validation for sync traffic. libcurl's automatic redirect following allowed a malicious sync peer to redirect the request to internal network resources. An attacker who is a configured sync peer, controls a feed source URL, or can influence DNS resolution for a configured endpoint can exploit this to cause the MISP server to issue requests to arbitrary internal services, potentially reading sensitive data or interacting with internal APIs that are not otherwise exposed. Affected: MISP versions prior to 2.5.52.

CVE-2026-135250

Published: 2026-11-23 10:17:44 CDT

Severity: N/A

CVSS Score: N/A

MISP contains a denial-of-service vulnerability in its image processing pipeline. When generating attachment thumbnails or rendering event graph preview images, the application decodes user-supplied image data using the GD library without first validating the declared pixel dimensions in the image header. Because GD allocates its pixel buffers outside the scope of PHP's memory_limit directive, a crafted image with an extremely large declared resolution (for example, 20000 x 20000 pixels) can trigger a multi-gigabyte memory allocation during the decode step, exhausting available system memory and causing the PHP worker process or the host to become unresponsive. Preconditions: - An authenticated MISP user with permission to upload attachments or to create/view event graphs. - The ability to supply a crafted image file (e.g., a PNG with a valid header declaring oversized dimensions). Impact: - Denial of service: memory exhaustion leading to process crash or host unavailability. - No confidentiality or integrity impact is indicated by the evidence. Affected versions: MISP prior to 2.5.52.

MISP contains an authorization flaw in the Sharing Group Blueprint execution path. When a blueprint is executed, it rewrites the organisation roster of the associated sharing group. CVE-2026-135241

Published: 2026-11-23 10:17:42 CDT

Severity: N/A

CVSS Score: N/A

MISP contains an authorization bypass vulnerability in the handling of Galaxy and Galaxy Cluster publish/unpublish operations. The application failed to enforce consistent permission checks when users attempted to unpublish a Galaxy or Galaxy Cluster. Specifically, the unpublish action only required the 'perm_galaxy_editor' permission, whereas the publish action required both 'perm_galaxy_editor' and 'perm_publish'. This inconsistency allowed a user from a different organization who possessed the 'perm_galaxy_editor' permission but lacked the 'perm_publish' permission to unpublish a Galaxy or Galaxy Cluster created by another organization. This action could disrupt the availability of shared threat intelligence data for other users and organizations relying on that cluster. The vulnerability affects MISP versions prior to 2.5.52.
