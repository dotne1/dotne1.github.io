CVE-2026-125658

Published: 2026-11-24 10:17:53 CDT

Severity: N/A

CVSS Score: N/A

Use After Free vulnerability in Erlang/OTP erts allows an attacker who can create a file system entry with a chosen name to hang or abort the Erlang VM on macOS. On macOS, the VM decodes file names with do_utf8_to_list_normalize in erts/emulator/beam/erl_unicode.c. When a name starts with a combining mark, such as U+0301, cleanup_norm builds the first list cells but does not return its advanced heap pointer. The caller then releases the heap words that hold those cells, and the returned list refers to released process heap memory that the next allocation overwrites. file:list_dir/1, file:list_dir_all/1, file:del_dir_r/1 and filelib:wildcard/1 on a directory that contains such a name do not return, and the VM does not stop on SIGTERM. file:read_link/1 on a symbolic link with such a target aborts the VM with size_object: bad tag. Only loss of availability was demonstrated. This issue affects OTP from OTP 17.0 before OTP 27.3.4.20, OTP 28.5.0.9, and OTP 29.1.3, corresponding to erts from 6.0 before 15.2.7.15, 16.4.0.8, and 17.1.2.

CVE-2026-65622

Published: 2026-11-24 09:17:39 CDT

Severity: N/A

CVSS Score: N/A

Improper Encoding or Escaping of Output vulnerability in ex-aws ex_aws_ses (ExAws.SES module) allows path injection into Amazon SES V2 request URLs. This vulnerability is associated with program file lib/ex_aws/ses.ex and program routines ExAws.SES.delete_contact_list/1, ExAws.SES.get_contact_list/1, ExAws.SES.update_contact_list/2, ExAws.SES.create_contact/3, ExAws.SES.get_contact/2, ExAws.SES.update_contact/3, ExAws.SES.delete_contact/2 and ExAws.SES.list_contacts/1. The V2 contact-list and contact functions interpolate the caller-supplied list_name into the request path without URI-encoding it, unlike the email address in the same functions which is passed through ExAws.Request.Url.uri_encode/1. An application that forwards untrusted input as a contact-list name lets an attacker embed /, .. or ? to escape the intended contact-lists/ path segment. A value such as x/../suppression/addresses/victim%40example.com makes a delete_contact_list/1 call arrive at the account-wide suppression list. The request is still signed with the application's own AWS credentials and sent to the configured SES host, so the impact is cross-resource request forgery inside the caller's own AWS account, not arbitrary SSRF. Applications that only use hardcoded or strictly validated list names are not affected. This issue affects ex_aws_ses: from 2.3.0 before 2.5.0.

CVE-2026-65621

Published: 2026-11-24 09:17:39 CDT

Severity: N/A

CVSS Score: N/A

ex_aws_s3 builds x-amz-meta-* request headers by interpolating user-supplied object metadata directly into header names and values without any validation. In ExAws.S3.Utils.build_meta_headers/1 (lib/ex_aws/s3/utils.ex), each :meta entry is turned into a header as {"x-amz-meta-#{k}", v} with no check for carriage return (CR), line feed (LF), or other illegal header bytes. Object metadata is routinely derived from end-user input (for example an upload service that lets users attach a comment or label to an object). When such input reaches ExAws.S3.put_object/4 or any other operation accepting the :meta option, a value containing CR/LF is carried unchanged into the outbound header list. If the configured HTTP adapter does not neutralize header values before writing them to the socket, the embedded CRLF starts a new header line, allowing an attacker to inject arbitrary headers into (or split) the HTTP request the library sends to the S3 endpoint. This is an HTTP header (CRLF) injection leading to HTTP request splitting. The practical impact depends on the HTTP adapter, and no authentication is required beyond the ability to influence object metadata. This issue affects ex_aws_s3: from 2.0.0 before 2.6.0.

CVE-2026-63585

Published: 2026-11-24 09:17:38 CDT

Severity: N/A

CVSS Score: N/A

ExAws.S3 constructs S3 ACL grant headers (such as x-amz-grant-read and x-amz-grant-full-control) in format_grant_header/1 by interpolating grantee identifiers into a quoted, comma-separated list without escaping. Grantee email and id values are wrapped in double quotes and joined with a comma, but double-quote, comma, and CR/LF characters in the value are not neutralized. An application that passes an attacker-influenced grantee value (for example an email address taken from a "share this object" feature) into an ACL grant option (grant_read, grant_write, grant_read_acp, grant_write_acp, or grant_full_control) lets the attacker close the quoted token and inject an additional grantee, such as the attacker's own canonical id or the predefined AllUsers group URI, into the header. S3 then applies the injected grantee, granting an arbitrary principal the same permission (up to full control or public access) in an unintended ACL grantee-injection and privilege-escalation issue. This issue affects ex_aws_s3: from 2.0.0 before 2.6.0.
