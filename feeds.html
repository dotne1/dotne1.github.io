CVE-2026-129814

Published: 2026-11-21 07:16:41 CDT

Severity: LOW

CVSS Score: 3.1

The SDO Information Get Object Description and Get Entry Description responses copy the object or entry name into the mailbox data area and then write a null terminator byte. The copy loops ran up to the last available byte in the buffer, leaving no room for the terminator. When an object or entry name exactly fills the available space the terminator is written one byte past the end of the mailbox data buffer.

CVE-2026-129813

Published: 2026-11-21 07:16:41 CDT

Severity: MEDIUM

CVSS Score: 5.3

The CoE complete-access download handler iterated over all subindices of an object and wrote the master-supplied payload into each writable entry. Entries that hold a constant have write-access flags set but carry a NULL data pointer. The handler did not check for this and wrote the master payload through the NULL pointer.

CVE-2026-129812

Published: 2026-11-21 07:16:41 CDT

Severity: MEDIUM

CVSS Score: 5.3

An object dictionary entry that holds a constant has no process data storage and carries a NULL data pointer. sizeOfPDO did not check for this when resolving a mapped entry to its descriptor. A master that maps such an entry to a PDO causes COE_pdoPack or COE_pdoUnpack to dereference the NULL data pointer on every process data exchange after the mapping is activated.

CVE-2026-129811

Published: 2026-11-21 07:16:40 CDT

Severity: HIGH

CVSS Score: 8.8

The PDO mapping bit lengths stored in the mapping objects are writable by the master via SDO. sizeOfPDO summed them without checking the total against the size of the rxpdo[] or txpdo[] process data buffers. A master can craft a mapping whose total bit count exceeds those buffers, causing COE_pdoPack and COE_pdoUnpack to write past their ends during each process data cycle after the PREOP to SAFEOP transition.

CVE-2026-129810

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 5.3

ESC_eoeprocess and ESC_eoeprocess_tx can be reached before the application calls EOE_config to supply the callback table pointer. When eoe_cfg is NULL the receive handler dereferenced it while processing an incoming EoE frame, and the transmit polling function dereferenced it on each cycle, causing NULL pointer dereferences.

CVE-2026-129809

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 5.3

ESC_foeprocess can be reached by an incoming mailbox frame before the application calls FOE_config to supply the file table and flush buffer pointers. When foe_cfg or its fbuffer field is NULL the handler dereferenced those pointers while processing the frame, causing a NULL pointer dereference.

CVE-2026-129808

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 6.5

The EoE receive and transmit paths call the handle_recv_buffer and fetch_send_buffer callbacks without first checking whether they are set. Both callbacks are documented as optional; an application that omits either one causes a call through a NULL function pointer when the first EoE frame arrives or when the transmit polling loop runs.

CVE-2026-129807

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 6.5

The FoE file table allows entries to omit a write handler by setting write_function to NULL, making the file read-only. FOE_fopen did not check whether write_function was present before accepting a write request; a master sending a WRQ for a read-only file caused a call through a NULL function pointer.

CVE-2026-129806

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 5.3

The CoE SDO upload handler enters its normal-response path (used for objects longer than 4 bytes) and passes (objd + nsub)->data directly to the pre-object handler and to the response copy. Entries that hold a constant in the value field have data set to NULL; a master can request such an entry and cause a NULL pointer dereference in the upload path.

CVE-2026-129805

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 5.3

An object dictionary entry can carry write-access flags and still have a NULL data pointer, for example when a constant value is held in the value field rather than in addressable storage. The CoE SDO download handler checked write access but not whether storage was present, then wrote the master-supplied payload through the NULL pointer.

CVE-2026-129804

Published: 2026-11-21 07:16:40 CDT

Severity: MEDIUM

CVSS Score: 4.2

FOE_read and FOE_write store the filename length as uint8_t, truncating it modulo 256. When (mbxheader.length - ESC_FOEHSIZE) is a multiple of 256, the length becomes 0. Additionally, a request whose mailbox length equals ESC_FOEHSIZE exactly also produces a length of 0 without any truncation. In both cases FOE_fopen calls strncmp with a length of 0, which always returns equal, so the first registered file whose password is 0 is opened regardless of the filename the master sent.

CVE-2026-129803

Published: 2026-11-21 07:16:39 CDT

Severity: MEDIUM

CVSS Score: 4.3

The CoE entry gate accepts frames with mbxheader.length as low as COE_MINIMUM_LENGTH (8), but a normal SDO Download requires at least COE_HEADERSIZE (10) bytes of CoE payload to carry its header fields. With mbxheader.length of 8 or 9, the segmented-transfer branch misevaluates due to unsigned wrap, leaving the declared SDO size unclamped. copy2mbx then reads that many bytes starting past the end of the actual payload and writes them into the object buffer.

CVE-2026-129802

Published: 2026-11-21 07:16:39 CDT

Severity: MEDIUM

CVSS Score: 4.3

EOE_set_ip reads each network parameter field (MAC, IP, subnet, gateway, DNS IP, DNS name) from the mailbox payload before checking whether the payload is large enough to contain them. The single bounds check at the end of the function does not prevent the reads from happening. A master can send a Set-IP frame with all flags set and mbxheader.length equal to the minimum, causing all reads to access memory past the end of the payload.

CVE-2026-129801

Published: 2026-11-21 07:16:39 CDT

Severity: HIGH

CVSS Score: 7.1

The FoE DATA frame handler computes the payload length from the master-supplied mailbox length field and passes it directly to FOE_fwrite. The length is checked against the remaining file capacity but not against the physical mailbox buffer size. A master can declare a large length while sending a short frame, causing FOE_fwrite to read past the end of the mailbox buffer.

CVE-2026-129800

Published: 2026-11-21 07:16:39 CDT

Severity: MEDIUM

CVSS Score: 6.5

sizeOfPDO, called during state transitions, uses the subindex-0 count of the SM-assign and PDO-mapping objects as loop bounds without checking those counts against the descriptor array sizes. On builds where those subindex-0 values are writable via SDO, a master can write 0xFF and cause sizeOfPDO to read past the end of the descriptor arrays on the next transition to SAFEOP.

CVE-2026-129798

Published: 2026-11-21 07:16:39 CDT

Severity: HIGH

CVSS Score: 8.8

The CoE SDO segmented download handler advances a write pointer by each incoming segment's size but does not track how many bytes have been written in total. A master can keep sending non-last segments until the pointer has walked past the end of the object buffer or the complete-access staging buffer.

CVE-2026-129797

Published: 2026-11-21 07:16:39 CDT

Severity: HIGH

CVSS Score: 8.8

SDO_downloadsegment is called whenever a mailbox frame carries the DOWNLOADSEGREQ command byte, regardless of whether a segmented download is actually in progress. ESCvar.data, which the handler writes through, is NULL until a segmented transfer is started. A master can send a DOWNLOADSEGREQ at any time and write through a NULL or stale pointer.

CVE-2026-129796

Published: 2026-11-21 07:16:38 CDT

Severity: HIGH

CVSS Score: 8.8

The CoE SDO download handler for flexible-length objects (VISIBLE_STRING, OCTET_STRING, and similar) does not check that the master-declared transfer size fits within the object before writing. Two distinct writes are affected: the VISIBLE_STRING zero-padding memset and the first-frame copy into the object buffer.

CVE-2026-129795

Published: 2026-11-21 07:16:38 CDT

Severity: MEDIUM

CVSS Score: 6.5

When the last EoE fragment has the TIME_APPEND flag set, the handler subtracts 4 from rxframeoffset to strip the timestamp. There is no check that rxframeoffset is at least 4. A fragment carrying fewer than 4 bytes of payload that is also marked LAST causes rxframeoffset to wrap to 0xFFFFFFFC, which is then stored as the buffer length and handed to the TCP/IP stack.
