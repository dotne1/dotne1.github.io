CVE-2026-136881

Published: 2026-11-25 08:17:08 CDT

Severity: N/A

CVSS Score: N/A

In the `setup-osc` GitHub Action of Eclipse Apoapsis, from commit 4e9eaff up to, but not including, commit 03efc4c, the ORT Server version returned by the `/api/v1/versions` endpoint is inserted into a shell script via a GitHub Actions expression without validation. An attacker who controls the responses of the configured ORT Server, for example by compromising the server, can execute arbitrary commands on the GitHub Actions runner and access the secrets available to the calling workflow. The issue is fixed in commit 03efc4c, which only accepts version strings consisting of alphanumeric characters, `.`, `+`, and `-`.

CVE-2026-136863

Published: 2026-11-25 08:17:08 CDT

Severity: N/A

CVSS Score: N/A

In Eclipse Apoapsis ORT Server versions 0.1.0 to 0.83.0, the file-based configuration providers do not restrict resolved file paths to the configured directory. An authenticated user who is allowed to trigger an ORT run for a single repository can use `../` sequences or absolute paths in `reporter-template://` references of the reporter job configuration to make the reporter worker read arbitrary files and include them in the generated reports. This discloses files such as environment variables, mounted secrets, and configuration files that contain credentials shared across all tenants of the server. The issue is fixed in Eclipse Apoapsis ORT Server 0.84.0.
